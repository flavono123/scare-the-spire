작성일: 2026-11-02. 코드 변경 없는 기획 문서다. 수치 중 공수와 기준값은 제안값이고, 나머지는 조사 시점의 repo, 채널 뷰, 소식지 데이터 기준이다.

## 2. 공통 판단

### 장난감 상자 vs 별도

- 장난감 상자는 URL 접두사가 없는 메뉴 묶음이다(`src/lib/site-nav-items.ts`). 나중에 옮겨도 URL이 깨지지 않으므로 지금 싼 쪽을 고르면 된다.
- 별도 섹션은 항목 2개에 과하다. 내비 2곳(메인, 패치 Worker), ko/en 문구, 토큰, 알림 점 집계가 늘고 모바일 검색창이 줄어든다.
- 현재 표시 행은 9개다. 2개를 더해 11개면 약 360px로 한도 384px 안에 든다(계산값).
- `/defragment` 하위는 맞지 않는다. 그 묶음은 피드와 글쓰기를 전제한다. `create-toybox-service` 기본값의 예외로 명시한다.
- 최상위 행은 `createdAt` 내림차순이라 새 게임이 조각모음보다 위에 온다. `toybox-nav.spec.ts`는 통과한다.
- 혼자 하는 게임이 3개가 되거나 표시 행이 12개가 되면 묶음을 다시 본다.

### 재화를 넣지 않는 이유

- **쓸 곳이 없다.** 아바타, 팔레트, 펫이 모두 무료라 해금을 만들면 있던 기능을 뺏는 셈이다.
- **벌 곳이 유한하다.** 베타 정답 후보 336개, Connections 26개에 월 1개다.
- **위조를 막을 수 없다.** 베타는 이미지 파일명이 정답이고, Connections는 정답이 클라이언트 JSON에 있다.
- **잔액을 복구할 수 없다.** 로그인이 없고 익명 ID는 브라우저에 묶인다.
- **근거가 없다.** 재화 수요를 보여 주는 신호가 없다.

두 부담에 대한 답:

- **운영:** 분쟁, 복구, 남용, 제출물 검수가 없다. 실패해도 메뉴에서 숨기면 끝이다. 남는 고정 작업은 Connections 월 1개(15~20분 추정)이고 소식지 작업에 끼워 넣는다.
- **기술:** 원장이 없으므로 Supabase Free의 반복 멈춤이 게임을 막지 못한다. Pro 전환은 현재 서비스의 신뢰성 문제로 따로 판단한다.

### 재화를 다시 볼 조건

아래를 모두 만족할 때만 연다.

1. 게임 방문과 재방문이 실제로 확인된다. 기준값은 사이트 방문 기준선을 본 뒤 정한다.
2. 잔액 차감 없이는 만들 수 없는 쓸 곳을 한 문장으로 정의할 수 있다. 칭호와 도감은 달성 플래그로 되므로 불합격이다.
3. 로그인, 처리방침과 약관, 분쟁 처리를 맡기로 한다.
4. 원장이 Supabase Free 멈춤과 분리되어 있다.

로컬 기록은 위조할 수 있어 재화로 옮기지 못한다. 재화가 생기면 0에서 시작하므로 지금 대비할 것은 없다. 기록에 `v` 필드와 안정 ID를 두고, 파생값 없이 사실만 저장하는 정도면 된다. 이는 재화와 무관하게 필요하다.

### 저장 구조

| 데이터 | 위치 | Supabase 멈춤 시 |
|---|---|---|
| 문제, 퍼즐, 정답 | 정적 JSON | 영향 없음 |
| 플레이 기록 | localStorage `sts-beta-art-v1`, `sts-vexing-puzzlebox-v1` | 영향 없음 |
| 방문 측정 | Cloudflare Web Analytics | 영향 없음 |
| 댓글(2단계) | 완료 뒤 지연 로드 | 게임은 계속되고 댓글만 멈춤 |

전역 레이아웃의 `CommentCourier`와 nav-seen 조회는 그대로 돈다. "게임 경로 무의존"이지 "페이지 전체 무의존"은 아니다.

두 서비스 모두 일일 모드와 연속 기록을 넣지 않는다. 공급이 유한해 고갈되고, 끊긴 연속 기록을 되살릴 수단도 없다. 대신 번호가 붙은 아카이브로 간다.

## 3. 베타 아트

### 채널에서 읽은 수요

48편 중 45편이 공개 상태다. 수치는 채널 뷰가 OAuth 실패로 비어 있어 `stats` 표에서 직접 읽었고, 복구 뒤 다시 확인해야 한다.

| | 베타 아트 1~42편 | 그 외 42편 |
|---|---|---|
| 조회 합 | 42,489 | 39,158 |
| 좋아요율 | 0.45% | 0.32% |
| 댓글 있는 편 | 21 | 12 |

- 조회는 시리즈와 무관하게 편당 약 1,000회로 수렴한다. 구독자는 29명이다.
- 저장된 시청자 댓글 35개(작성자 24명) 중 18개가 농담과 드립이고, 6개가 귀엽다는 반응이다.
- **갤러리 요청 0건.** 가까운 신호는 "어떻게 보나" 1건, 소장 관심 1건이다.
- **퀴즈 근거 0건.** 맞히기 시도가 없지만, 영상이 정식 → 베타 순서에 판당 1.2초라 추측을 유도한 적이 없다. 즉 측정되지 않았다.
- 그림을 보고 카드 이름으로 지목하는 댓글이 약 11건 있다. 약한 간접 신호다.
- 베타/정식 비교 의견은 1~2건뿐이다.

소재 반응은 약간 높지만 표본이 작다. 소비 방식은 어설픈 그림을 보고 웃고 공유하는 쪽이라, 설명보다 나란히 보기와 그림 공유가 맞다.

이 내용은 만들지 말지가 아니라 요구사항을 정하는 근거로 쓴다.

### 쇼츠 연결

- 베타 → 멈춤 → 정답 순서의 추측형 쇼츠는 출시 홍보용으로 낸다. 관문이 아니다. 제작은 slseoun-shorts 쪽 일이다.
- 쇼츠 설명 링크는 클릭되지 않는 것으로 알고 있으며 확인은 못 했다. 유입은 채널 프로필 링크, 영상 안 자막, 고정 댓글의 텍스트 주소에 기댄다.

### 출시 범위

- **경로:** `/beta-art` 1개. 쿼리로 `?mode=quiz`, `?set=12`, `?item=...`을 둔다. 레코드 URL과 `__id__` 셸은 만들지 않는다.
- **갤러리 336점:** 카드 272 + 베타만 있는 3(맹화, 광분, 회피) + 유물 38 + 파워 2 + 역사 21. 타입, 캐릭터, "EA에서 본 베타" 필터를 둔다. 마지막 필터는 PCK로 검증된 카드 49장에만 쓴다.
- **제외:** 그림이 같은 카드 9장, 공식 이름 없는 유물 14장, 연결 안 된 유물 파일 6장, 몬스터 5장, STS1 302장.
- **퀴즈:** 베타 그림을 보고 카드 이름을 4지선다로 고른다. 274문항을 10문항씩 고정 묶어 27세트로 만든다. 카드 275장에서 창백한 푸른 점을 뺐다(검은 화면에 점 하나).
- **공개 연출:** 정답을 낼 때 베타와 정식을 나란히 보여 준다.
- **출제 규칙:** 오답은 같은 캐릭터 풀에서 뽑고, 작은 풀(퀘스트, 저주, 상태이상)은 합친다. 픽셀이 비슷한 베타 12쌍은 같은 문제에 넣지 않는다.
- **공유:** 결과 문구 복사(점수, 맞음/틀림 격자, 세트 링크). 그림 쌍 이미지 복사는 합성 구현이 새로 필요해 2단계로 미룬다.
- **쇼츠 연결:** 재생목록 링크 1개.

## 4. Connections

### 사실

- 빙고가 아니라 16개 항목을 4개씩 4그룹으로 묶는 Connections 형식이다.
- 니오우스레터 2호(2024-09)부터 26개가 실렸다. #1~#27 중 #22가 없다.
- 문서 author는 Mega Crit이고, 소식지 표현은 "official unofficial"이다. 그래서 "Mega Crit이 만든 퍼즐"까지만 말할 수 있고 "공식"과 "허가받음"은 쓰지 않는다.
- 제작기는 Claire Wang의 개인 사이트다. 정답은 공개 Firestore 문서에 있고 인증 없이 읽힌다. 26개를 모두 읽어 확인했다.
- 그쪽이 사라지면 소식지 링크도 죽는다. repo에는 스크린샷뿐이라 정답이 없다.

### 번역 맵 대조

26개, 416항목 전부 공식 한국어 이름이 있다. 구멍은 0개다.

- **게임 jar에만 있음(12):** 사건 9(잊힌 제단, 영묘, 붉은 가면 왕의 무덤, 황금 성소 2, 모닥불 정령들, 추락, 성직자, 신성한 샘), 육각령, 입마개, 부패한 두리안.
- 네메시스는 STS2 파워로 잘못 대조됐다. #14는 STS1 몬스터이므로 `ref`를 직접 지정한다. 호기심 묶음의 분노도 카드가 아니라 파워다.

STS1 사건, 몬스터, 파워, 블라이트는 `scripts/extract-sts1-compendium.py` 흐름으로 jar에서 현지화를 뽑아 `data/sts1/localization`에 추가한다.

### 출시 범위

- **경로:** `/vexing-puzzlebox`, 쿼리 `?p=27`. 스포일러 없는 공유 미리보기는 어차피 같아서 `__id__` 셸은 만들지 않는다.
- **대상:** 개발은 최근 #27 하나로 시작한다. 배포 전에 26개를 전부 backfill하고 STS1 렌더도 함께 넣는다. 나눠서 배포하지 않는다.
- **규칙:** 16칸에서 4개 선택, 실수 4회. 칸 배치는 번호 시드 셔플과 다시 섞기.
- **강화 시점:** 풀기 전에는 공식 한국어 이름 텍스트만 보인다. 외형 기준 묶음은 그림이 곧 정답이기 때문이다. 묶음을 맞히면 그림과 호버 렌더, 백과사전 링크를 연다. 끝나면 전체 그림과 카테고리 설명을 낸다.
- **재사용:** `patch-note-renderer.tsx`의 `GameResourcePreview`, `EntityPreview`, `entityCompendiumHref`, `useCoarsePointer` 탭 미리보기.
- **공유:** 이모지 격자 텍스트 복사. 항목 이름과 카테고리는 넣지 않는다.
- **소식지 연결:** `claimId`로 해당 소식지 항목에 게임 링크를 렌더한다. `.ko.md` 본문은 번역 규칙상 건드리지 않는다.
- **빠지는 것:** 댓글, 일일 모드, 연승, 퍼즐별 OG, 사용자 제작과 제출. 댓글은 CLAUDE.md의 "모든 요소에 댓글" 방향에 따라 2단계에 완료 뒤 지연 로드로 붙인다.

### 데이터

`data/sts2-connections.json` 하나만 둔다. 강화본에 원문이 전부 들어가므로 raw 디렉터리는 두지 않는다.

```json
{ "number": 27, "issueId": "2026-10", "claimId": "connections-27",
  "slug": "ntI593ipwd4eQvMzC2hL", "era": "sts2", "defaultLabel": "official",
  "categories": [{ "level": 0, "titleEn": "...", "titleKo": "...", "noteKo": null,
    "members": [{ "raw": "...", "ref": { "game": "sts2", "type": "relic", "id": "..." } }] }] }
```

- 이름은 저장하지 않고 `ref`로 언어별 공식 이름을 푼다. 모든 항목에 `ref`가 있어야 하며 `null`은 허용하지 않는다.
- `era: "sts1"` 퍼즐은 STS1 이름으로 푼다. 예: Sozu는 소주, Paper Krane은 종이 학.
- `ref.type`은 필수다. #27처럼 카드와 파워가 이름을 공유한다. 대조에는 단복수 정규화가 필요하다(Blessed Antlers, Whispering Earrings).
- 이식 스크립트는 작성 시점에 문서를 한 번씩 읽는다. 검증은 4묶음, 묶음당 4개, 중복 없음, level 고유, `ref` 존재, `era` 일치를 본다.
- 신규 월은 `neowsletter` 스킬에 단계를 추가한다. `data/sts2-connections*`는 main Worker로만 배포되므로, 소식지 페이지가 이 JSON을 읽게 하면 워크플로 분기에 추가해야 한다.

### 언어

- 항목은 언제나 게임 공식 이름으로 낸다. 영어 기본 표기는 없다.
- 카테고리 제목은 서비스 번역이다. kor, eng 외 gameLocale 12개는 항목만 현지어, 카테고리는 영어로 낸다.
- 영어 단어 놀이에 기대는 묶음은 104개 중 4개다. 공식 이름 그대로 내고, 정답 공개 때 `noteKo`로 영어 이름의 공통점을 설명한다.

| 퍼즐 | 묶음 | 깨지는 지점 |
|---|---|---|
| #11 | 이름에 신체 부위가 든 카드 | 냉정함(Coolheaded), 전투장비(Armaments) |
| #11 | 유명 영화 제목과 같은 카드 | 진정한 끈기, 불의의 일격, 천적, 의심 |
| #12 | 유명 게임 제목과 같은 항목 | 황금 눈, 격노, FTL, 황금 우상 |
| #23 | 해변에서 하는 일인 카드 | 착수(Splash), 안식(Relax), 난사(Volley) |

- 항목 교체와 한국어 재출제는 하지 않는다. 그건 이식이 아니라 새 창작이다.

## 5. 단계

공수는 1인 + 에이전트 기준의 근거 없는 추정이다. 선례는 Supabase 쓰기 유무가 달라 직접 비교가 안 된다.

| 단계 | 내용 | 공수 | 진입 조건 |
|---|---|---|---|
| 베타 1 | 정체성, 라우트 등록, `?beta=true` 수정, 카탈로그, 갤러리, 퀴즈, 문구 공유, 전수 검증 | 3~4일 | 없음 |
| 베타 2 | 유물·역사·파워 문항 +61, 확대 크롭 모드, 그림 쌍 복사, 항목별 쇼츠 링크, 댓글 | 2~3일 | 베타 1 배포 뒤 |
| 커넥션 1 | #27로 목록과 플레이, 저장, 공유, 출처 문구, 소식지 링크 | 2~3일 | 없음 |
| 커넥션 2 | 25개 backfill, STS1 현지화 추출, STS1 렌더, 전수 검증 | 1~2일 | 커넥션 1, 배포 전 필수 |
| 커넥션 3 | 댓글 | 미정 | 배포 뒤 |
| 상시 | Connections 월 1개 | 월 15~20분 | |

베타 2와 커넥션 3의 진행 여부는 6절의 8주 판단을 따른다.

인덱스 라우트 1개는 정적 자산 약 30개다. 현재 18,485 / 19,500이라 들어가지만, 착수 전 `pnpm cf:assets`로 다시 확인한다.

## 6. 측정

측정 수단은 Cloudflare Web Analytics뿐이다. 토큰은 코드에 있다. 리퍼러, 쿼리 구분, SPA 경로 집계와 서비스별 방문 기준선은 착수 전에 대시보드에서 확인한다. 완주율은 잴 수 없으므로 지표에서 뺀다.

판단은 출시 8주 시점에 두 서비스 모두 같은 기준으로 한 번 한다.

- **계속:** 4주 연속 주간 방문이 장난감 상자 서비스 중앙값 이상이거나, 외부 공유·언급이 5건 이상.
- **중단:** 주간 방문이 중앙값의 절반 미만이고 공유·언급이 0건. 메뉴에서 숨기고 URL은 유지한다.
- **즉시 내림:** Mega Crit의 요청이 오면 지표와 무관하게 내린다.

기준선을 본 뒤 수치를 조정한다.

## 7. 소유자 결정

확정: 베타 아트를 만든다. Mega Crit에 문의하지 않는다. 영어 기본 표기는 없다. Connections는 #27로 시작해 26개 backfill 후 배포한다.

남은 것은 **기준 수치**(8주 기준)뿐이고, 방문 기준선을 본 뒤 조정한다.
