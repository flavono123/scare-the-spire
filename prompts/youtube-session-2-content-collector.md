## 목표

유튜브 쇼츠 대본을 채울 **주제 동향**을 관측하고, 그 중 일부를 스크립트 재료로 고를 수 있게 한다. 시작은 **스킬이면 충분**하다. 텔레메트리 대시보드·별도 앱은 스킬이 반복 사용되고 한계가 드러난 뒤에만 제안한다. 제안 시 `.codex/skills/cf-guardrails/SKILL.md`와 `.codex/skills/feature-implementation/SKILL.md`를 읽는다. 디시 스크랩을 Worker 요청 경로에 넣지 않는다.

완료 조건 (1차):

1. `.codex/skills/` 아래 스킬이 있다. description에 트리거(슬갤, 동향, 유튜브 대본, 과거 시점 조사)가 있다.
2. 에이전트가 스킬을 따라 **지금** 동향을 가져오면 아래 출력 스키마를 채운다.
3. **과거 특정 시점**(날짜 또는 패치 버전+전후 N일)을 같은 스키마로 조사할 수 있다. 초반 유튜브는 이 모드를 더 많이 쓴다.
4. 출력은 모니터링용으로 **주제 많이**, 스크립트용으로 **추천 소수**를 나눈다. 추천만 주고 끝내지 않는다.
5. 각 추천 주제마다 유형, 본문 원문(발췌), 댓글 1·2·3, 원문 링크가 있다.
6. 법적 게이트(창작글 전문, 스트리머 클립, 선정, 실명 저격)가 스킬에 있고, 플래그가 붙은 항목은 추천에서 빠진다.

## 채널이 원하는 재료

쇼츠 한 편 = 주제 하나 + 본문 한 방 + 댓글 연극 3줄. 공략 전문·망호·FAQ 념글은 조회가 높아도 채널 센티멘트가 아니다.

유형 시드 (가중치는 `재미-메모리`로 나중에 조정):

- 패치 멘붕 / 고평가 뒤집힘
- 런 사망 스크린샷의 타이밍
- 카드·유물 한줄 과대/과소 (옵평 구조)
- 번역·이름 드립 (게임 말 그대로)
- 멀티/고대 도박 실패의 동질감

금지: 슬망호, 공략 모음, 설문, 창작글/팬픽/팬아트 재배포, 중괄호 등 방송 클립, 펀치라인이 성드립인 글, 특정 닉 매장.

## 수집기이자 모니터

운영자는 올린 편수보다 **훨씬 많은 주제**를 보고 고른다.

한 번의 실행 출력은 두 층이다.

1. **관측 보드** — 주제 8–20개. 제목, 유형, 소스, 열기(추천/댓글/시간), 한 줄 왜 뜨는지, 리스크 플래그. 원문 전부 붙이지 않아도 된다. 링크는 필수.
2. **스크립트 후보** — 그중 2–5개. 각 항목에 본문 발췌 + 댓글 1·2·3 원문 + 링크. 발췌는 하이라이트용이지 장문 전문이 아니다.

에이전트가 1등만 고르고 나머지를 숨기면 실패다.

## 시점: 지금 / 트리거 / 과거

스킬은 모드를 받는다.

- `now` — 최근 48h (또는 운영자가 준 창) 슬갤 개념글 + 화제성 일반글. 실시간의 대부분은 망호이므로 추천수 상위 = 재미 상위가 아니다.
- `trigger` — 패치 당일, 베타 드롭, 운영자가 “지금 긁어”라고 한 순간. 패치 버전은 사이트의 슬서운변경/패치 데이터와 맞출 수 있으면 맞춘다.
- `historical` — **유튜브 초반에 가장 많이 쓴다.** 예: `2026-05-01 ~ 2026-05-07`, `v0.107 전후 3일`, `작년 이맘때 슬갤`. 그 구간의 념글·댓글 급증 글을 같은 스키마로 가져온다.

과거 조사 방법(구현 시 되는 것부터):

- 슬갤 검색·개념글의 날짜 필터, 글 번호/작성 시각.
- 디시 비공식 대량 덤프 API를 만들어 우회하지 않는다. 공개 웹을 사람이 보듯 보고, 필요하면 운영자 브라우저로 확인한다.
- 결과를 스킬 로컬 메모(운영자 머신, gitignore)에 남기면 같은 주를 다시 조사할 때 링크가 산다. `public/`이나 Worker에 디시 원문을 미러하지 않는다.

디시 이용약관상 무단 전재·기계적 수집은 회색이다. 이 스킬은 **운영자 한 명이 대본을 고르기 위한 관측**이지 공개 아카이브 서비스가 아니다. 원문은 유튜브 설명란 링크 + 짧은 인용만 전제로 한다.

## 출력 스키마

스킬이 에이전트에게 이 형태를 강제한다. YAML이든 Markdown 표든 필드만 빠지지 않으면 된다.

```text
mode: now | trigger | historical
window: { from, to, tz: KST }
patch_context: { version or null, note }

watchlist:           # 모니터. 많게
  - topic: 
    type: 
    source: slgall | other | slseoun
    heat: 
    why: 
    url: 
    flags: []

script_candidates:   # 선별. 적게
  - topic:
    type:
    body:
      excerpt:        # 읽을 문장만. 전문 덤프 금지
      url:
      author_label:   # 갤닉 정도. 신상 없음
    comments:
      - text:
        url:
      - text:
        url:
      - text:
        url:
    flags: []
    skip_reason: null | ...
```

`script_candidates`에는 댓글이 3개 안 되면 2개라도 적고 부족하다고 표시한다. 억지로 광고·분쟁 댓글을 채우지 않는다.

## 스킬 설계 제약

- SKILL.md는 짧게. 루브릭·스키마·소스 비중·금지 목록. 긴 DC URL 패턴은 `reference.md`.
- 실행 스크립트가 필요하면 `scripts/`에 두고, 디시 HTML을 깨는 스크래퍼를 기본 경로로 두지 않는다. 브라우저 도구로 공개 페이지를 읽는 쪽이 1차에 맞다.
- 사이트 앱/텔레메트리로 키울 때: 수집은 빌드 타임·로컬·운영자 머신. Cloudflare Worker에서 디시·슬갤을 매 요청마다 치지 않는다.
- 재미 메모리 파일은 사이트 레포와 분리하거나 gitignore한다. 채널 운영 메모를 `src/`에 넣지 않는다.
- 광범위한 파일 이동·라우트 추가는 사용자 승인 없이 하지 않는다 (`AGENTS.md` Broad File Changes).

## 작업 순서

1. 기존 캔버스의 발굴 탭·게이트를 읽고 스킬에 옮긴다. 호빈이/채린이 같은 제작 세부와 섞지 않는다.
2. 슬갤 공개 웹 구조(개념글, 글 페이지, 댓글, 작성 시각)를 확인한다.
3. SKILL.md + 출력 예시를 만든다.
4. `now`로 한 번 돌려 관측 보드 + 후보를 실제로 채운다. 빈 스키마만 남기지 않는다.
5. `historical`로 운영자가 줄 법한 예(최근 패치 주 또는 한 달 전 일주일)를 한 번 돌려 같은 스키마가 나오는지 본다.
6. 한계(검색 날짜가 부정확, 삭제글, 개념글 편향)를 스킬에 적는다.

한국어로 보고한다. 코드/주석은 영어. 의미 있는 수정 후 `main`에 영어 커밋. `public/generated` 등 static:data 산출물은 커밋하지 않는다.
