## 결론부터

지금 하나를 서비스 후보로 고른다면 **`쓰레기 더미`**다.

`쓰레기 더미`는 한 자원인 전리품만으로 `더 깊이 / 지금 회수`를 반복할 수 있다. 영구 재화 없이도 무엇을 들고 나왔고 무엇을 잃었는지가 결과물이 되며, 같은 시드 재도전과 공유도 자연스럽다.

가장 작은 검증판은 **`미끄러운 다리`**다. 원작 이벤트가 이미 `현재 표시된 카드를 덱에서 제거한다 / 체력을 잃고 제거 후보를 다시 뽑는다`를 반복한다. 6장짜리 임시 덱만 먼저 보여주면 서버 없이도 20초짜리 push-your-luck을 검증할 수 있다.

가장 강한 **아이덴티티**는 `웡고스 랜덤 박스`다. 다만 아이덴티티와 게임 루프를 구분해야 한다.

- 원작의 100/200/300은 위험 단계가 아니라 세 상품의 가격이다.
- 원작의 5는 미니게임 카운터가 아니라 티켓 구매 뒤 기다리는 전투 수다.
- 유물 3개, 웡고 포인트, 고객 감사 배지는 원작에 있다.
- 베팅, 할당량, 카운터, 결과 영수증은 서비스가 새로 만드는 규칙과 연출이다.

초안의 600골드·5카운터 규칙은 100골드만 고르면 완주가 보장되는 지배 전략이 있었다. 조기 체크아웃도 런 밖의 부분 보상이 없어 가짜 선택이었다. 따라서 웡고스는 배당표의 모든 경로를 열거해 지배 전략이 없음을 확인하기 전까지 장기 서비스 1순위로 확정하지 않는다.

권장 순서는 다음과 같다.

1. `미끄러운 다리`로 세션 안의 “한 번 더 버틴다”를 검증한다.
2. 같은 철수 기계인 `쓰레기 더미`를 5층 런으로 확장한다.
3. 공유 링크 유입이 실제로 생기는지 확인한 뒤에만 비동기 선택을 붙인다.
4. 웡고스는 별도로 1카운터에서 위험·배당을 검증한 뒤 3카운터로 늘린다.

핵심 명제는 간단하다.

> 약한 신원에서는 보상을 계정에 저장하지 않는다. 한 판에서 생긴 사건, 결과 영수증, 같은 시드, 친구의 실수를 보상으로 만든다.

`일일`은 입장권이나 재화 지급 주기가 아니라 **오늘 모두가 같이 겪는 무대**로만 쓴다. 오늘 시드는 무제한 재도전할 수 있어야 하고, 무한 연습과 공유된 시드는 날짜와 무관하게 항상 열려 있어야 한다. 즉시 재도전은 세션 반복이지 재방문이 아니므로, D1/D7은 공유 유입과 같은 브라우저 귀환을 별도로 측정한다.

## 1. 신원 제약을 코드 기준으로 다시 정의

현재 구현은 국가·IP·OS·디바이스 조합으로 한 사람을 식별하는 구조가 아니다.

- [use-auth.ts](../src/hooks/use-auth.ts)는 쓰기가 필요할 때 Supabase 익명 세션을 만든다.
- [user-profile.ts](../src/lib/user-profile.ts)는 닉네임·캐릭터·펫 같은 프로필을 `localStorage`에 둔다.
- [run-store.ts](../src/lib/run-store.ts)는 런을 IndexedDB에 로컬 우선으로 저장한다.
- [I18N.md](../docs/I18N.md)는 프로필을 인증·권한이 아닌 휘발성의 근사 신원으로 취급한다.
- ISR은 신원 체계가 아니다.

즉 현실적인 계약은 **“같은 브라우저에서는 어느 정도 이어지지만, 같은 사람임을 보장하거나 복구할 수는 없는 익명 세션”**이다.

이 계약에서 가능한 것과 불가능한 것은 다음과 같다.

| 가능 | 이유 |
|---|---|
| 한 런 안의 골드·체력·유물 | 런이 끝나면 가치도 끝난다. |
| 로컬 최고 기록·연승 | 초기화돼도 금전·소유권 손실이 없다. |
| 브라우저의 농담성 배지 전시함 | “쓸모없음” 자체가 웡고 원문의 개그다. |
| 전 세계 공통 시드 | 날짜와 버전만으로 재현할 수 있다. |
| 결과 링크·시드·선택 기록 | 사람 대신 런을 식별하면 된다. |
| 익명 응답 집계 | “사람 수”가 아니라 “플레이/응답 수”로 표기하면 된다. |

| 피해야 함 | 이유 |
|---|---|
| 희소 재화·한정 소유권 | 초기화·다중 세션·조작이 실제 손실과 분쟁을 만든다. |
| 거래·선물 인벤토리 | 소유권과 중복 방어가 필요해진다. |
| 공정성을 주장하는 세계 랭킹 | 익명 세션 재생성과 클라이언트 조작을 막을 수 없다. |
| 강제 1일 1회·출석 스트릭 | 신뢰성도 낮고 놓쳤을 때의 손해만 만든다. |
| 상품·돈과 연결된 확률 | 현재 신원과 공정성 모델 모두에 맞지 않는다. |
| 기기 간 영구 진행 | 계정 복구 계약 없이는 약속할 수 없다. |

따라서 이 서비스의 가치 단위는 `userId`가 아니라 다음이어야 한다.

```text
gameDataVersion + rulesVersion + seed + choices[] = 재현 가능한 한 런
```

## 2. 기존 아이디어가 멈춘 이유

### 2.1 수정구

[CRYSTAL-SPHERE.md](./CRYSTAL-SPHERE.md)는 비용과 운영 위험을 아주 잘 줄였다.

- 서울 날짜 기반 전역 시드
- 모두 같은 카드 3장과 유물/포션 1개
- 재굴림 없음
- 서버 저장·순위·댓글 없음
- 공유 URL

하지만 비용과 함께 플레이도 제거됐다.

1. 날짜가 바뀌는 것이 유일한 변화다.
2. 사용자가 운을 바꾸거나 감수할 선택이 없다.
3. 한 번 본 뒤 다시 눌러도 새 사건이 생기지 않는다.
4. 좋은 결과와 나쁜 결과 모두 “이미 정해진 이미지 묶음”으로 끝난다.
5. 친구가 링크를 열어도 같은 결과를 볼 뿐, 둘 사이에 새 행동이 생기지 않는다.

수정구의 실패 원인은 “일일”이어서가 아니라 **일일 결과 자체를 게임과 보상으로 취급한 것**이다.

수정구 아트와 원문은 버릴 필요가 없다. `분할 납부`라는 훌륭한 위험 선택도 이미 있다. 다만 독립 서비스보다 웡고스의 보너스 방, 혹은 무한 연습이 있는 `점을 치는 법` 모드로 재사용하는 편이 낫다.

### 2.2 Tiny Card 3-match 룰렛

현재 저장소의 `public/images/sts2/tiny-card/`는 카드 597장의 미니 초상화가 아니라 배너·설명 상자·그림자 같은 공통 합성 부품이다. 기존 Tiny Card만으로는 카드 ID를 구분할 수 없다. 카드별 릴이 필요하면 기존 전체 카드 아트를 직접 렌더하거나, 별도 표현을 빌드 시 합성해야 한다. 사전 합성만이 유일한 구현 방법은 아니다.

더 큰 문제는 “같은 그림 3개”가 STS2와 관계없는 보편 슬롯 규칙이라는 점이다.

- 왜 이 조합이 좋은지 게임 지식으로 설명할 수 없다.
- 코인이 남지 않는다면 점수도 의미가 없다.
- 코인을 영구 저장한다면 약한 신원 문제가 돌아온다.
- 첫 잭팟을 본 뒤에는 새 사건보다 애니메이션 반복만 남는다.

살리려면 같은 이미지가 아니라 **게임 속 속성 족보**를 맞춰야 한다.

- 같은 색 / 같은 타입 / 같은 희귀도
- 공격·스킬·파워 한 장씩
- 같은 키워드
- 같은 파워를 적용하는 카드
- 저주가 끼면 깨지는 조합
- 한 릴을 고정하고 나머지만 다시 뽑는 제한된 통제

이 형태는 독립 서비스보다 웡고스의 20초짜리 카운터 하나로 먼저 검증하는 편이 낫다.

### 2.3 월드컵

[007-world-cup-service-todo.md](../tasks/007-world-cup-service-todo.md)가 보류한 이유도 비슷하다.

- 무작위 토너먼트의 판단 기준이 모호하다.
- 의미 있는 결과를 만들려면 전역 집계가 필요해진다.
- 익명 다중 투표를 막기 시작하면 인증 문제가 핵심이 된다.
- 한 번 우승자를 고른 뒤 같은 대진을 다시 볼 이유가 약하다.

“무엇이 더 좋은가”를 묻는 기존 [이것이냐 저것이냐](/this-or-that)와 겹치므로 새 라우트가 될 이유도 약하다.

### 횡단 결론

성공 사례의 공통점은 영구 재화가 아니다.

1. **랜덤이 상황을 만들고 사용자가 위험을 선택한다.**
2. **현재 확률이나 손실 가능성을 읽을 수 있다.**
3. **실패는 현재 런만 끝내며, 실패 장면은 결과물로 남는다.**
4. **한 판보다 3~7개의 작은 결정을 연결한 런이 강하다.**
5. **친구는 보너스가 아니라 선택에 책임을 지는 재료다.**
6. **일일 갱신이 없어도 런 조합과 친구가 재방문을 만든다.**
7. **일일을 쓸 때도 무제한 재도전과 같은 시드 학습이 있다.**

슬서운이야기에 옮길 공식은 다음과 같다.

```text
60~180초 런
  = 3~7개의 되돌릴 수 없는 선택
  + 보이는 위험
  + 1~2회의 제한된 확률 개입
  + 한 번의 큰 공개
  + 실패 원인이 적힌 결과 영수증
```

## 4. 이 프로젝트에 맞는 설계 헌법

### 4.1 플레이

1. 첫 설명 전에 눌러볼 수 있는 선택 하나를 보여준다.
2. 한 런은 60~180초를 목표로 하고 20초 안에도 실패할 수 있게 한다.
3. 자원은 체력·골드·욕심 중 하나만 전면에 둔다.
4. 무작위 결과는 `계속 / 회수`, `보존 / 재추첨`, `혼자 / 친구에게 넘김` 중 하나로 통제한다.
5. 후보 풀, 남은 위험 카드 수, 혹은 최소한 위험 등급을 공개한다.
6. 실패 직후 새 게임 버튼보다 먼저 “왜 망했는지”를 보여준다.
7. 결과는 점수 하나가 아니라 유물·카드·몬스터가 보이는 영수증 또는 부고장으로 만든다.

### 4.2 재방문

재방문 입구를 날짜 하나에 몰지 않는다.

- 즉시 같은 시드 재도전
- 즉시 새 시드
- 친구가 보낸 봉인 링크
- 이어달리기 차례
- 오늘의 공통 시드
- 새 패치로 바뀐 후보 풀
- 브라우저의 농담성 영수증 전시함
- 백과사전 상세 페이지로 이어지는 결과 카드

`오늘의 도전`은 다음 조건을 모두 만족할 때만 쓴다.

- 오늘 안에 무제한 재도전 가능
- 놓친 날에 손해 없음
- 무한 연습이 항상 별도로 존재
- 어제 시드도 링크로 재현 가능
- 같은 시드를 다시 해서 배운 정보가 실제로 도움 됨

### 4.3 소셜

실시간 멀티플레이는 필요 없다.

- 링크를 받은 친구가 선택 하나만 더한다.
- 같은 시드를 각자 플레이하고 결과를 나란히 본다.
- 발신자가 두 결과 중 하나를 봉인하고 수신자가 고른다.
- 한 사람은 후보를 보고 다른 사람은 선택만 한다.
- 결과에 각 선택을 한 순서만 기록해 “누가 망쳤나”를 보여준다.

자유 텍스트는 처음에는 받지 않는다. 게임 데이터와 정해진 선택지만 공유하면 스팸·모더레이션·신고 체계를 만들 필요가 없다.

### 4.4 보상

- 런 안의 골드·체력·유물은 런과 함께 끝난다.
- 결과 카드와 공유 링크가 진짜 보상이다.
- 로컬 배지·연승은 “이 브라우저에만 저장되며 초기화될 수 있음”을 숨기지 않는다.
- 웡고 포인트처럼 쓸모없음이 원문 농담인 숫자만 장기 표시한다.
- 실제 돈, 유료 재도전, 유료 확률 변경, 상품과 연결하지 않는다.

## 7. 상위안 상세 기획

### 7.1 1순위 — 웡고스 랜덤 박스

#### 한 줄

가상의 골드로 5개의 카운터를 버티고, 끝까지 살아남으면 봉인된 유물 3개와 쓸모없는 영수증을 받는 60~180초 런.

#### 게임 근거

`WELCOME_TO_WONGOS` 이벤트에는 다음 선택이 실제로 있다.

- `웡고스 할인 코너`: 100골드, 무작위 일반 유물 1개
- `웡고스 추천 상품`: 200골드, 무작위 유물 1개
- `웡고스 랜덤 박스`: 300골드, 5번의 전투 후 무작위 유물 3개
- 떠나면 무작위 카드 1장 열화
- 구매 뒤 웡고 포인트와 웡고스 고객 감사 배지를 안내하는 대사

출처는 [events.json](../data/sts2/localization/kor/events.json)의 `WELCOME_TO_WONGOS.*`다.

#### 제안 루프

1. 런 전용 600골드와 웡고스 랜덤 박스 티켓을 받는다.
2. 다섯 카운터를 차례로 지난다.
3. 매 카운터에서 100/200/300골드 중 하나를 건다.
4. 첫 검증 모드는 카드 비용 또는 유물 희귀도의 `높다 / 낮다` 하나만 쓴다.
5. 후보 풀과 현재 승산을 보여주고, 한 번만 `엿보기` 또는 `다시 진열`을 쓸 수 있다.
6. 틀리면 건 골드를 잃고, 맞히면 런 전용 골드를 받는다.
7. 언제든 체크아웃할 수 있지만, 다섯 카운터를 모두 통과해야 티켓의 유물 3개가 공개된다.
8. 마지막에 잔액, 선택 로그, 가장 무리했던 선택, 유물 3개, 웡고 포인트 0점이 적힌 영수증을 만든다.

100/200/300 가격, 5번 뒤 유물 3개, 웡고 포인트·배지는 원작에서 가져온다. 600 시작 골드, 배당, 카운터 규칙은 서비스 규칙임을 구분한다.

#### 도파민과 통제

- 봉인된 유물 3개는 마지막까지 남는 큰 공개다.
- 매 판 결과가 아니라 `위험 단계`를 사용자가 고른다.
- 전체 후보와 승산을 보이므로 순수 가챠가 아니다.
- 엿보기·다시 진열 중 하나만 쓸 수 있어 “아껴 쓰다 망한” 이야기가 생긴다.
- 5카운터라는 짧은 마감이 한 판을 늘어뜨리지 않는다.

#### 보상

- 진짜 보상: 유물 3개가 보이는 영수증, 실패 원인, 시드 링크
- 농담 보상: 이 브라우저에만 쌓이는 쓸모없는 웡고스 배지
- 쓰지 않을 것: 영구 골드, 유물 소유권, 교환, 세계 순위

#### 재방문

- 즉시 새 진열
- 같은 시드에서 다른 위험 단계
- 친구가 보낸 영수증의 같은 진열
- 오늘의 웡고스 진열: 전 세계 공통, 무제한 재도전
- 새 패치로 바뀐 카드·유물 풀

#### 비동기 friendslop

MVP 뒤에 하나만 붙인다.

- 발신자가 5카운터 중 4개를 진행한다.
- 마지막 카운터를 봉인해 친구에게 보낸다.
- 수신자의 한 선택으로 유물 3개가 열리거나 런이 망한다.
- 영수증에 누가 어떤 선택을 했는지만 기록한다.

실시간 방, 친구 목록, 초대 코드, 소유권은 필요 없다.

#### MVP에 넣을 것

- 카드 또는 유물 `높다 / 낮다` 한 모드
- 5카운터
- 100/200/300 위험 단계
- 후보 풀·현재 승산
- 1회 엿보기
- 티켓 유물 3개 공개
- 결과 영수증
- 새 시드 / 같은 시드 / 링크 복사
- 로컬의 쓸모없는 배지 숫자

#### MVP에서 뺄 것

- 여러 미니게임
- 유물 효과 시뮬레이션
- 친구 이어하기
- Supabase 저장
- 동적 OG 이미지
- 세계 랭킹
- 영구 인벤토리
- 실제 댓글 연결

### 7.2 2순위 — 쓰레기 더미

#### 한 줄

한 층씩 더 깊이 들어가 잊힌 카드와 유물을 회수하고, 사고가 나기 전에 전리품을 들고 나오는 회수 게임.

#### 게임 근거

`TRASH_HEAP` 이벤트는 다음 선택을 실제로 제공한다.

- `아무 고물이나 잡는다`: 골드와 과거의 무작위 잊힌 카드
- `뛰어든다`: 체력을 잃고 과거의 무작위 잊힌 유물
- 사망 문구: 쓰레기 더미 안에 너무 깊게 뛰어들었다

#### 제안 루프

1. 표면에서 잊힌 카드 1장과 낮은 가치의 고물을 본다.
2. `회수 / 더 깊이`를 고른다.
3. 깊어질수록 잊힌 유물과 희귀 후보가 늘고 사고 위험도 오른다.
4. 사고가 나면 휴대한 전리품 하나가 고철로 바뀌거나 런이 끝난다.
5. 3~7층 사이에서 회수하면 적재 목록을 받는다.

반복 층, 파손, 위험 곡선은 서비스 규칙이다. 카드·유물 풀과 이벤트 문구는 추출 데이터에서만 가져온다.

#### 왜 강한가

- R.E.P.O.처럼 정상 행동인 “더 가져오기”가 사고를 만든다.
- 무엇을 잃었는지 이미지로 보이므로 실패가 구체적이다.
- 폐기·과거 데이터가 테마와 기능 양쪽에서 자연스럽게 쓰인다.
- 결과 콜라주가 전리품 산과 사망 원인을 동시에 보여준다.

#### 최소판

- 5층
- `회수 / 더 깊이`
- 층별 위험 등급 공개
- 카드·유물 각각 한 풀
- 결과 적재 목록
- 같은 시드

친구 릴레이와 물건별 효과는 반응이 확인된 뒤에만 붙인다.

### 7.3 가장 작은 검증판 — 미끄러운 다리

#### 한 줄

지금 보이는 카드를 받고 다리를 건널지, 체력을 잃고 `버틴다`를 눌러 카드를 다시 뽑을지 고른다.

#### 게임 근거

원작 `SLIPPERY_BRIDGE` 자체가 이미 이 반복을 갖고 있다.

- `헤쳐 나간다`: 현재 무작위 카드를 덱에서 제거
- `버틴다`: 체력을 `3+` 잃고 상단 카드가 무작위로 변경
- `HOLD_ON_0`부터 `HOLD_ON_LOOP`까지 점점 무너지는 공식 대사
- 사망 문구: 미끄러져 떨어졌다

#### 검증하려는 한 가지

> 사용자는 계정 보상이 없어도, 현재 결과를 버리고 더 나은 결과를 보기 위해 한 번 더 누르는가?

#### 최소판

- 시작 체력
- 현재 카드 한 장
- `헤쳐 나간다 / 버틴다`
- 원작 단계별 대사
- 사망 또는 획득 결과 카드
- 즉시 새 시드 / 같은 시드

서버, 일일, 영구 점수, 친구 기능이 전혀 필요 없다. 이 모드에서도 즉시 재도전이 나오지 않으면 더 큰 확률 서비스에 경제나 배지를 붙여도 해결되지 않을 가능성이 높다.

### 7.4 인형의 방

#### 한 줄

체력을 아끼고 인형 하나를 눈감고 고를지, 5 또는 15를 내고 후보를 더 볼지 결정하는 선택 게임.

#### 게임 근거

`DOLL_ROOM` 이벤트의 실제 선택은 다음과 같다.

- `아무거나 고른다`: 무작위 인형 유물 1개
- `잠시 고민한다`: 체력 5를 잃고 2개 중 1개
- `깊게 고민한 뒤 최고의 선택을 한다`: 체력 15를 잃고 3개 중 1개

#### 제안 루프

1. 체력 25로 세 개의 인형장을 지난다.
2. 각 장에서 무료 블라인드 / 5를 내고 2개 / 15를 내고 3개를 고른다.
3. 인형 하나를 챙길 때마다 남은 체력과 마지막 장의 선택 폭이 달라진다.
4. 세 인형과 소비한 체력, 가장 후회한 선택을 결과 카드로 만든다.

#### 비동기 버전

- 발신자가 인형 3개 중 하나를 봉인한다.
- 수신자가 남은 두 개 중 하나를 고른다.
- 마지막에 둘의 인형과 남겨진 인형을 같이 공개한다.

“무엇을 소유했나”가 아니라 “친구가 무엇을 남겼나”가 보상이므로 계정이 필요 없다.

### 7.5 니오우의 뼈 주사위

#### 한 줄

니오우 유물 둘과 저주 하나를 굴리고, 일부를 고정한 채 두 번 다시 굴리는 30초 주사위.

#### 게임 근거

`NEOWS_BONES`의 실제 효과는 다음이다.

> 무작위 니오우 유물 2개를 획득하고 덱에 무작위 저주 1장을 추가한다.

`NEOW` 데이터에는 현재 니오우 유물 목록이 명시되어 있다.

#### 제안 루프

1. 두 개의 유물 면과 한 개의 저주 면을 공개한다.
2. 한 번에 최대 두 면을 고정할 수 있다.
3. 남은 면을 최대 두 번 다시 굴린다.
4. 최종 축복 조합과 포기한 결과를 한 장에 보여준다.

유물 사이의 가짜 시너지 점수는 만들지 않는다. 희귀도·풀·카드 설명처럼 추출된 속성만 표시한다. 족보가 필요해질 때도 “유물 둘의 희귀도가 같다”처럼 검증 가능한 규칙만 쓴다.

### 7.6 다음 의도 맞히기

#### 한 줄

몬스터의 현재 행동과 상태를 보고 다음 의도를 세 개 중 고른다.

#### 강점

- 행동 그래프가 실제 정답과 전이 확률을 제공한다.
- 지식과 운이 같이 작용한다.
- 같은 몬스터를 다시 보면 학습이 실제로 쌓인다.
- 무한 연습, 오늘의 5문제, 같은 시드가 모두 성립한다.
- [monster-intent-fsm.ts](../src/lib/monster-intent-fsm.ts)와 기존 의도 시각화를 재사용할 수 있다.

#### 주의

이 안은 훌륭한 백과사전 게임이지만 friendslop 사건은 약하다. 독립 서비스보다 아래의 `백년퍼즐` 여러 모드 중 대표 모드로 묶는 것이 낫다.

### 7.7 도박용 칩

#### 한 줄

카드 5장을 받고 원하는 만큼 한 번 버려, 색·타입·희귀도·키워드 족보를 만든다.

#### 강점

- `GAMBLING_CHIP`의 “원하는 만큼 버리고 다시 뽑는다”는 기억과 직접 연결된다.
- Balatro처럼 알려진 족보와 STS2 규칙을 겹칠 수 있다.
- 같은 시드에서 무엇을 버렸는지가 실력과 후회를 만든다.

#### 주의

완전한 포커 점수표를 처음부터 만들지 않는다. 첫 검증은 다음 6개 족보면 충분하다.

- 같은 색 3장
- 같은 타입 3장
- 같은 희귀도 3장
- 공격·스킬·파워
- 같은 키워드 2장 이상
- 저주 없는 손

## 10. 수정구와 3-match를 살리는 구체안

### 10.1 수정구는 `오늘의 결과`가 아니라 `분할 납부` 모드로

살릴 요소:

- `수정구` 제목과 이벤트 배경
- “타일을 열어 당신의 미래를 드러내 보세요!”
- 소형/대형 점술
- 좋은 결과·나쁜 결과 banter
- `분할 납부`

바꿀 요소:

1. 항상 새 시드로 무한 플레이할 수 있다.
2. 오늘의 구체는 같은 타일 배치일 뿐, 시도 횟수를 막지 않는다.
3. 6회 점술 중 언제든 결과를 회수할 수 있다.
4. 위험 타일을 열면 이미 얻은 결과 하나가 뒤집히거나 저주가 붙는다.
5. 한 번만 타일을 엿보거나 두 타일의 위치를 바꿀 수 있다.
6. 결과에 개봉 순서와 “이 타일에서 멈췄어야 했다”를 표시한다.
7. 친구에게 미개봉 타일 하나를 넘길 수 있다.

이렇게 하면 기존 문서와 카피 후보 파일을 버리지 않으면서, 날짜 대신 욕심이 게임을 움직인다.

### 10.2 Tiny Card는 3-match가 아니라 3-reel 족보로

최소 규칙:

1. 실제 카드 그림 3장이 릴에 나온다.
2. 첫 회전 뒤 릴 하나를 고정할 수 있다.
3. 나머지를 한 번만 다시 뽑는다.
4. 6개의 읽을 수 있는 족보만 판정한다.
5. 저주가 나오면 족보 하나가 깨지지만, 희귀한 `저주 셋`도 별도 결과가 된다.
6. 결과는 코인이 아니라 세 카드와 족보 이름이 있는 레시피 카드다.

데이터 기반 족보 예:

- 한 색 3장
- 공격·스킬·파워
- 한 희귀도 3장
- 공통 키워드 2개 이상
- 같은 파워를 적용하는 카드 2개 이상
- 저주 3장

첫 구현은 독립 라우트가 아니라 웡고스의 카운터 모드 하나가 맞다. 이 모드에서 반복과 공유가 확인되면 그때 별도 서비스 승격을 판단한다.

## 11. 보상 체계

### 11.1 영구 재화 대신 세 겹의 보상

#### 즉시 보상

- 큰 공개 애니메이션
- 유물·카드·포션 이미지
- 성공/실패 원인이 적힌 한 줄
- 아슬아슬했던 확률

#### 런 보상

- 영수증
- 전리품 적재 목록
- 사망 부고
- 선택 타임라인
- 같은 시드 링크

#### 약한 메타 보상

- 이 브라우저의 최고 층
- 발견한 결과 카드 전시
- 쓸모없는 웡고스 배지
- 몬스터별 퍼즐 숙련

메타 보상은 초기화돼도 서비스 의미가 무너지지 않아야 한다. 내보낼 수 있는 링크와 결과 화면이 진짜 소장품이고, 브라우저 전시함은 편의 기능이다.

### 11.2 숫자를 쓴다면

- `사용자 1,234명`이 아니라 `오늘 1,234회 플레이`
- `생존자 31%`가 아니라 `완료된 응답 중 31%`
- 세계 1위가 아니라 `이 브라우저 최고 기록`
- 검증된 승률이 아니라 `현재 후보 풀 기준 확률`

조작돼도 가치가 생기지 않는 숫자만 서버에 둔다.

## 12. 기술 형태

### 12.1 런타임

MVP는 서버 저장 없이 성립해야 한다.

```text
빌드 타임
  원본 JSON
    → 유효 데이터 필터
    → 모드별 작은 manifest
    → 정적 JSON과 정적 이미지

브라우저
  rulesVersion + gameVersion + seed
    → 고정 PRNG
    → 3~7개 선택
    → 결과 영수증
    → URL fragment에 seed + choices
```

- Worker 요청에서 전체 카드·유물·패치 JSON을 파싱하지 않는다.
- 관계 조인과 문제 생성은 빌드 시 한다.
- 한 런은 상수 개수의 후보만 읽는다.
- 배경·카드·유물은 기존 정적 자산을 쓴다.
- 런별 동적 OG 이미지는 만들지 않는다.
- 첫 공유는 일반 페이지 URL과 시드, 결과 카드 UI면 충분하다.
- URL fragment가 짧은 선택 로그를 담으면 서버에도 전송되지 않는다.

### 12.2 저장

| 데이터 | MVP 저장 |
|---|---|
| 현재 런 | React 상태 또는 `sessionStorage` |
| 로컬 최고 기록·배지 | `localStorage` 또는 기존 로컬 런 저장 패턴 |
| 공유 시드·선택 | URL fragment |
| 익명 플레이 수 | 반응 검증 뒤에만 Supabase |
| 친구가 이어가는 가변 런 | 공유 링크 반응이 확인된 뒤 capability URL 검토 |

클라이언트 결과는 조작 가능하다고 전제한다. 경제와 랭킹이 없으므로 서명·안티치트·핑거프린팅을 만들 이유가 없다.

### 12.3 패치 대응

- 결과 URL에 `gameDataVersion`과 `rulesVersion`을 함께 넣는다.
- 과거 시드는 가능하면 해당 버전 manifest로 재현한다.
- 과거 manifest를 영원히 보관하지 않는다면 “현재 버전으로 다시 굴림”을 명시한다.
- 새 패치는 후보 풀을 바꾸는 자연스러운 콘텐츠 업데이트다.

### 12.4 Cloudflare Free

- 런타임 SSR, 마크다운 변환, 전체 데이터 조인, 이미지 합성, AI 문구 생성을 하지 않는다.
- 모드별 manifest는 빌드 시 작게 만든다.
- 결과 카드는 클라이언트에서 렌더한다.
- 공유용 서버 행이 필요해져도 선택 로그 몇 개만 담고 만료시킨다.
- 여러 모드를 만들더라도 한 런에서 필요한 파일만 지연 로드한다.

- 새 시드 / 같은 시드

통과 기준 제안:

- 시작한 플레이의 절반 이상이 한 런을 끝낸다.
- 완료 플레이의 25% 이상이 즉시 한 번 더 시작한다.
- 실패와 성공 사이의 재도전 차이가 지나치게 크지 않다.

숫자는 출시 예측이 아니라 다음 단계로 갈지 결정하기 위한 초기 기준이다. 기존 Toy Box의 같은 이벤트 정의가 있다면 절대 수치보다 상대 비교를 우선한다.

### 단계 1 — 웡고스 단일 모드

추가할 것:

- 5카운터
- 100/200/300 위험
- 1회 엿보기
- 유물 3개 지연 공개
- 영수증
- 쓸모없는 로컬 배지
- 링크 복사

통과 기준 제안:

- 5카운터 완료율이 단계 0의 짧은 런 대비 과도하게 떨어지지 않는다.
- 완료 플레이의 즉시 재도전이 25% 이상 유지된다.
- 결과 도달 대비 링크 복사가 5% 이상이거나, 기존 Toy Box 공유 기준보다 높다.
- 같은 브라우저의 7일 내 재방문이 기존 Toy Box 방문보다 의미 있게 높다.

### 단계 2 — 친구의 마지막 카운터

단계 1에서 실제 링크 복사와 링크 유입이 확인된 경우에만 만든다.

- 발신자가 4카운터를 끝낸다.
- 수신자가 마지막 선택을 한다.
- 둘의 선택이 영수증에 남는다.

통과하지 못하면 친구 목록, 실시간 방, 공유 DB를 추가하지 않는다. 먼저 결과 카드와 한 판의 재미를 고친다.

### 이벤트 이름

최소한으로 다음만 있으면 된다.

```text
toy_run_start
toy_choice
toy_run_finish
toy_retry
toy_share_copy
toy_shared_run_open
toy_friend_finish
```

`user`라는 이름 대신 `play`, `session`, `same-browser return`을 쓴다.

## 14. 공정성·접근성·윤리

도파민과 운을 쓰되 실제 도박의 불투명성과 손실 회피를 복제하지 않는다.

- 실제 돈과 연결하지 않는다.
- 유료 재도전·유료 확률 변경을 만들지 않는다.
- 후보 풀과 확률 또는 위험 등급을 표시한다.
- 결과를 미리 정해두고 가짜 선택을 주지 않는다.
- 놓치면 손해인 출석 스트릭을 만들지 않는다.
- “곧 사라짐” 같은 거짓 긴급성을 쓰지 않는다.
- 어린 이용자도 볼 수 있으므로 카지노 광고처럼 연출하지 않는다.
- 확률 게임임을 밝히고 실제 가치가 없음을 명시한다.
- 애니메이션은 `prefers-reduced-motion`에서 즉시 공개로 바뀐다.
- 흔들림·사인 효과가 정보 전달의 유일한 수단이 되지 않게 한다.
- 색만으로 버프·너프·위험을 구분하지 않는다.
- 모든 선택은 키보드와 스크린 리더 레이블을 지원한다.
- 긴 결과 애니메이션은 건너뛸 수 있다.

## 15. 하지 않을 것

1. 처음부터 웡고스에 여러 미니게임을 넣지 않는다.
2. STS2 전체 전투를 재현하지 않는다.
3. 유물 효과 사이의 가짜 시너지 엔진을 만들지 않는다.
4. 퀴즈 모드마다 라우트를 만들지 않는다.
5. 실시간 방·매칭·WebSocket을 만들지 않는다.
6. 자유 텍스트 UGC를 먼저 열지 않는다.
7. 계정 경제·희소 인벤토리·거래를 만들지 않는다.
8. IP·OS·디바이스를 사람으로 간주하는 핑거프린팅을 만들지 않는다.
9. 안티치트와 세계 랭킹을 만들지 않는다.
10. 런타임 AI 문구 생성이나 이미지 합성을 하지 않는다.
11. 일일 한 번만 누르고 끝나는 룰렛을 다시 만들지 않는다.
12. 공유가 검증되기 전에 동적 OG·짧은 URL 서버를 만들지 않는다.

## 16. 최종 추천 범위

하나를 고른다면 `웡고스 랜덤 박스`다.

첫 출시 범위는 다음 열 줄이면 충분하다.

1. 5카운터
2. 카드 또는 유물 `높다 / 낮다` 한 게임
3. 런 전용 골드
4. 100/200/300 위험 단계
5. 현재 후보 풀과 승산
6. 1회 엿보기
7. 5카운터 뒤 유물 3개 공개
8. 실패 원인이 적힌 영수증
9. 새 시드 / 같은 시드 / 링크 복사
10. 이 브라우저에만 쌓이는 쓸모없는 웡고스 배지

하지만 개발 착수 전 행동 가설은 `미끄러운 다리` 한 모드로 먼저 확인한다. 이 가장 작은 형태에서 즉시 재도전이 나오지 않으면, 웡고스의 세계관과 배지가 문제를 대신 해결해주지 않는다.
