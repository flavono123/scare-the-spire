# 버전 API 전수 조사 (구 빌드 정답 대조)

2026-10-19. 과거 모든 macOS 빌드(0.98.0 ~ 0.111.0, 26개 + 0.96.1/테스트 빌드 2개)를 `~/sts2-builds`에 받고([STS2_DEPOT_MANIFESTS.md](STS2_DEPOT_MANIFESTS.md)), 각 빌드의 dll/PCK에서 뽑은 값(`scripts/sts2_canonical_extract.py`)을 `getVersionedEntities` 결과와 항목 단위로 대조했다 (`scripts/audit-version-api-canonical.ts`). 회귀 테스트는 `pnpm test:version-canonical`이며, 지금 드리프트는 `scripts/versioned-canonical-baseline.json`(3,664건)에 고정돼 있어 **새 드리프트만** 실패한다 (아카이브가 없으면 건너뜀).

대조 항목: 카드(비용·종류·희귀도·변수·강화량·키워드), 유물/포션(희귀도·변수), 파워(변수), 몬스터(HP·피해/방어 수치·행동 ID·행동 그래프), 그리고 카드/유물/포션/파워/몬스터의 이름과 설명 템플릿(게임 자체 로컬라이제이션, eng/kor).

## 한눈에 보기

- 몬스터 수치는 대체로 정확하다: 비텍스트 불일치가 있는 몬스터는 22종뿐이고 대부분 행동 ID 개명/그래프 미기록이다.
- **카드·유물 수치**는 약 15장/몇 개에서 **빌드 전 버전 공통**으로 어긋난다. 그중 일부는 **현재(0.111.0) 데이터도 틀렸다** (아래 A).
- **설명/이름 텍스트**는 0.98.0에서 카드 99장·유물 36개가 빌드 원문과 다르고 최신 버전으로 갈수록 줄어 0.111.0에서 12건이다. 기존 `LOCALE_TEXT_PINNED_FROM = 0.104.0` 이전은 저작된 diff에 의존해서 생기는 차이다. 아카이브로 0.98.0부터 고정할 수 있다 (D).
- **존재 여부**(출시 전 카드가 보임, 삭제된 카드가 계속 보임)가 틀린 곳이 있다 (B).

## A. 현재(0.111.0) 데이터가 게임과 다른 곳 — 지금 서비스에 나오는 오류

소스(`CanonicalVars`/`OnUpgrade`)에서 직접 확인한 항목 (카드 JSON 값 → 게임 값):

| 카드 | 항목 | 데이터 | 게임 |
|---|---|---|---|
| 박살 (BREAK) | 강화 피해 | +5 | +10 |
| 잿불 (CINDER) | 강화 피해 | +5 | +6 |
| 대단원의 막 (GRAND_FINALE) | 강화 피해 | +10 | +15 |
| 왕의 발차기 (KINGLY_KICK) | 강화 피해 | +6 | +8 |
| 정밀 사격 (PINPOINT) | 강화 피해 | +5 | +4 |
| 왕의 주먹 (KINGLY_PUNCH) | 강화 피해 | 없음 | +2 |
| 덤벼라! (FIGHT_ME) | 힘 | 2 | 3 |
| 죽음의 무도 (DANSE_MACABRE) | 파워 수치 / 강화 | 3 / +1 | 4 / +2 |
| 영원의 갑옷 (ETERNAL_ARMOR) | 판금 / 강화 | 7 / +2 | 9 / +3 |
| 전장의 생존자 (WROUGHT_IN_WAR) | 제련 | 5 | 7 |

그 밖에 싸움 준비(`EXPECT_A_FIGHT`), 광채(`GLOW`), 스피드스터(`SPEEDSTER`), 검성(`SWORD_SAGE`), 벼락(`THUNDER`)은 값 차이이거나 추출기 한계라 개별 확인이 필요하다. 유물 설명 10개(`ALCHEMICAL_COFFER`, `BELT_BUCKLE`, `CAULDRON`, `DELICATE_FROND`, `DIAMOND_DIADEM`, `PHIAL_HOLSTER`, `SILKEN_TRESS`, `SOZU`, `TINY_MAILBOX`, `WHITE_BEAST_STATUE`)은 게임 원문에 `[gold]Potions[/gold]` 같은 키워드 표기가 있는데 데이터에는 없다 (0.111.0 텍스트 미반영으로 보임). 카드 설명은 칼날 교향곡(`BLADE_SYMPHONY`), 나선 관통(`HELIX_DRILL`).

수정 방법: 위 값을 정답 데이터로 고치고 설명 변수/강화 문구를 다시 굽는다. 이 문서의 대조가 끝난 뒤 값이 바뀌므로 baseline도 갱신한다.

## B. 버전별 존재 여부(수명 주기) 오류

API가 가용하다고 하지만 그 빌드에는 없던 카드 (처음 나온 빌드가 `introducedInPatch`로 기록돼 있지 않다 — 카드 598장 중 3장만 값이 있음):

| 카드 | 실제로 처음 나온 빌드 | API가 보여 주는 구간 |
|---|---|---|
| ABUNDANCE, DOWSING | 0.109.0 | 0.98.0 ~ 0.108.0 |
| BLADE_SYMPHONY, BLAZE, CACOPHONY, CONCOCT, CONSTELLATION, FADE, HIBERNATE, IMITATION_LEARNING, MIDNIGHT, ONE_FOR_ALL, OUTRAGE, PLOT, SOULBOUND, THE_BALL, UNDERWORLD | 0.108.0 | 0.98.0 ~ 0.107.1 |
| WITHER | 0.105.0 | 0.98.0 ~ 0.104.0 |

반대로 빌드에서 사라졌는데 API가 계속 보여 주는 카드: `GRAPPLE`(0.103.0부터 없음), `FOLLOW_THROUGH`(0.106.0부터 없음), `SCARE`(0.110.0부터 없음, 데이터는 `introducedInPatch: v0.106.0`만 있음).
유물 `SEAL_OF_GOLD`는 0.104.0까지 있었지만 데이터에서 삭제돼 과거 버전에서 **렌더할 곳이 없다**. 문을 만드는 자의 단계 파워(`HUNGER`/`SCRUTINY`/`GRASP`, 0.101.0~0.104.0)와 `DOOR_REVIVAL`(~0.99.1)도 파워 데이터가 없다.

## C. 몬스터

- 행동 ID가 개명된 몬스터는 과거 버전에서 **현재 ID**를 돌려준다 (`BOWLBUG_SILK`: 당시 `TRASH`, 지금 `THRASH` 등). 영향: 행동 이름/아이콘 매핑이 과거 ID로는 안 된다. `CUBEX_CONSTRUCT`, `BYGONE_EFFIGY`, `TUNNELER`, `QUEEN`, `TERROR_EEL` 등 16종.
- 변경 기록이 없는 구조 변화: `AXEBOT`(0.104 리워크의 행동 그래프), `PUNCH_CONSTRUCT`, `TEST_SUBJECT`(그래프), `HAUNTED_SHIP`, `SOUL_FYSH`(피해 수치), `WATERFALL_GIANT`(HP 250→240 시점), `DOOR`(HP).
- 이번 작업으로 잠행 군체·문을 만드는 자·땅굴 2인조·지하 선착장·깨작이·로켓·분쇄자·잊힌 자/사라진 자·조립 전문가 봇·실험체는 정답과 맞췄다.

## D. 텍스트

`LOCALE_TEXT_PINNED_FROM`(0.104.0) 이전은 게임 원문이 아니라 저작된 diff로 복원돼서, 0.98.0 기준 카드 99장·유물 36개·포션 일부의 설명/이름이 빌드 원문과 다르다 (예: ARSENAL 설명, BLADE_OF_INK이 0.100.0에서 후속 리워크 문구를 보임, `등반가의 골칫거리`가 `등반자…`로 보임). 아카이브의 PCK가 있으므로 `data/sts2/localization-history.json`을 0.98.0부터 다시 만들 수 있다 (`scripts/generate-localization-history.ts`는 git 이력 스냅샷을 쓰므로 아카이브를 입력으로 바꾸는 작업이 필요).

## E. 추출기의 한계 (불일치로 세어지지만 API 오류가 아닌 것)

- ILSpy가 배열 초기화 값을 버려서 `CanonicalKeywords`가 3개 이상이면 키워드를 알 수 없다 (`null`로 두고 대조 생략).
- 카드 변수의 파워 별칭(`Vulnerable` ↔ `VulnerablePower`) 규칙은 카드에만 적용된다. 파워 ID는 `_POWER` 접미사를 뗀다.
- `MAD_SCIENCE*` 변형 카드, 테스트 몬스터(`ONE_HP_MONSTER` 등)는 제외한다.
- 구 빌드의 async 메서드는 상태 기계로 디컴파일돼 `parse-monsters.py`가 파워 적용(힘 획득 등)을 읽지 못한다 (몬스터 대조는 HP/피해/방어/행동/그래프로 한정).
- 이번 조사 중 `parse-monsters.py`가 ILSpy의 `[CompilerGenerated] () => decimal.op_Implicit(X)` 람다를 읽지 못해 `THE_FORGOTTEN`의 Dread 피해가 0.100 이후 갱신되지 않던 문제를 고쳤다.
