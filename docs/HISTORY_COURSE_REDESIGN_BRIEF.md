# 역사 강의서 개편안 — 런 목록에서 “왜 봐야 하는 런”의 표지로

> **결정:** 서비스가 하이라이트를 판정하지 않는다. 작성자가 **볼 이유와 기준점**을 고르고, 서비스는 그 사실로 **표지 레이아웃 3개만** 제안한다. 인덱스는 이유를 먼저 보여주고, 상세는 같은 이유가 붙은 순간 또는 전체 런으로 바로 들어간다.

## 제안: “공유”를 작은 발행 과정으로 바꾼다

`런 업로드 → 볼 이유 작성 → 기준점 선택 → 표지 3안 중 선택 → 공개`

1. **볼 이유:** `조합이 터짐 / 억까·사고 / 복기 요청` 중 하나와 40자 안팎의 한 문장을 작성한다. 분류는 콘텐츠를 판정하는 규칙이 아니라 작성자의 의도이므로 새 조합이 생겨도 갱신할 휴리스틱이 없다.
2. **기준점:** `전체 런` 또는 재생기의 `층/노드 하나`를 작성자가 고른다. 관련 카드·유물·포션 2–4개는 해당 노드에서 실제로 등장한 항목을 먼저 채우고 작성자가 바꿀 수 있게 한다.
3. **표지 3안:** 모두 같은 작성자 선택을 다른 레이아웃으로만 표현한다.
   - **장면형:** 선택한 층의 지도·상단 상태·행동 스택을 멈춘 16:9 장면
   - **조합형:** 코오오옴보처럼 관련 카드·유물·포션을 겹친 16:9 포스터
   - **결말형:** 캐릭터·승천·승패/도달 층과 한 문장을 크게 보여주는 포스터

```text
┌────────────── 16:9 표지 ──────────────┐
│ [복기 요청] 34층 · 실험체              │
│ 지도 + 당시 체력 + 관련 카드/유물       │
└───────────────────────────────────────┘
방어 플랜은 있었는데 왜 여기서 무너졌지?
사일런트 · A10 · 49층 패배 · 댓글 7
```

### 인덱스

- 현재의 버전·시드·무작위 카드/유물보다 **표지, 볼 이유 한 문장, 승패/도달 층**을 우선한다.
- `복기 요청`은 댓글 수까지 보여줘 아직 답이 필요한 런을 알아볼 수 있게 한다. 정렬은 우선 최신순이면 충분하고 추천 알고리즘은 만들지 않는다.
- 검색은 작성 문장과 작성자가 고른 관련 카드·유물도 찾는다. “한마디 준비 중”인 공개 카드는 만들지 않는다.

### 상세 리플레이

- 상단에 인덱스와 같은 문장을 고정하고 선택한 층에 표식한다. **“이 순간부터 보기”**를 기본 행동으로, **“처음부터 보기”**를 나란히 둔다.
- `전체 런` 또는 `복기 요청`이면 요약을 먼저 열고 전체 재생으로 이어진다. 상세 하단에는 기존 댓글 UI를 재사용해 런 단위 복기를 받는다. 여러 순간별 댓글은 실제 사용이 확인된 뒤 추가한다.
- `.run`에는 방/턴 수, 체력·골드 변화, 획득·선택은 있지만 전투 중 카드 사용 순서·가한 피해·파워 상태는 없다([현재 타입](../src/lib/sts2-run-replay.ts#L60)). 따라서 표지는 **전투 영상이나 자동 검출된 순간이라고 주장하지 않고**, 작성자가 지목한 층의 사실과 관련 카드·유물을 보여준다.

## 가장 작은 구현

- 현재 인덱스의 카드·유물은 재미와 무관한 안정적 무작위 선택이다([선택 로직](../src/lib/run-highlights.ts#L20)). 이미 있는 `note_blocks`를 볼 이유 문장으로 살리고([기존 컬럼](../supabase/migration-012-runs-highlights-note.sql#L1)), `intent / focus act·step / layout / 관련 리소스`만 담는 작은 `cover_spec`을 추가한다.
- 공유 전 편집을 기본으로 하고, 공개 후 고칠 수 있도록 소유자 `update` 정책을 추가한다. 인덱스는 원본 런을 파싱하지 않고 이 작은 표지 정보만 읽는다.
- 이미 있는 코오오옴보의 [`aspect-video` 썸네일](../src/components/combo/combo-youtube-reference.tsx#L16)과 [리소스 겹침](../src/components/combo/combo-resource-stack.tsx#L132), 공용 [댓글 UI](../src/components/comment-section.tsx#L35)를 재사용한다. 표지는 이미지 생성물이 아니라 기존 에셋을 조립한 DOM이므로 Worker 요청 시 연산이나 별도 이미지 저장이 없다.

## 하지 않는 것과 판단 기준

**하지 않음:** AI 분석/생성, 자동 하이라이트 점수, 조합 사전, 지속 갱신 휴리스틱, 전투 영상인 척하는 재현, 추천 피드, 동적 OG 이미지, 여러 기준점.

**나중에 추가:** 한 기준점으로 복기가 부족하다는 실제 사용이 쌓일 때만 여러 표식이나 작성자 첨부 이미지/영상 타임스탬프를 검토한다.

개편 성공 여부는 세 가지만 본다: **공개 런의 상세 진입률**, **선택한 순간부터 재생한 비율**, **복기 요청당 댓글 수**. 이 셋이 오르지 않으면 더 똑똑한 탐지기가 아니라 표지 작성 마찰과 상세 진입 동선을 먼저 고친다.
