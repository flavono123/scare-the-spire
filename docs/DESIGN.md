# 디자인 가이드

슬서운이야기는 슬레이 더 스파이어 2 패치와 게임 데이터에서 출발하는 정보 사이트다. STS2 백과사전(Compendium)이 현재 서비스의 중심이며, 화면은 게임 위키보다 게임 안 백과사전에 가까운 밀도와 질감을 우선한다.

이 문서가 디자인·토큰·공통 컨트롤의 **정본**이다. 구현이 어긋나면 구현을 이 문서에 맞춘다. 게임에서 추출한 값(`StsColors`, hover tip 슬라이스, 공식 번역)이 이 문서보다 앞선다. Tailwind `*-500` 같은 프레임워크 기본값은 정본이 아니다.

로컬 Storybook(`pnpm storybook`)은 이 문서를 눈에 보이게 그리는 워크숍이다. Cloudflare Worker에는 포함하지 않는다.

## 정체성

- 한국어를 일급 시민 언어로 둔다.
- 게임에서 유래한 이름과 용어는 공식 번역을 우선한다.
- 데이터가 중심이다. 추측성 장식이나 서비스 편의로 만든 값보다 게임 원본/PCK/Steam 패치노트에서 확인된 정보를 우선한다.
- "엔티티"라는 표현은 UI에 쓰지 않는다. 카드, 유물, 포션, 몬스터, 이벤트, 고대의 존재처럼 직접 부른다.
- `Codex`라는 이름은 새 UI, 새 문서, 새 컴포넌트명에서 쓰지 않는다. 백과사전 canonical URL은 `/compendium`이며, 기존 `/codex` 라우트는 호환을 고려해 리다이렉트 대상으로 점진적으로 정리한다.
- 첫 화면은 실제 탐색/검색/비교가 가능한 도구여야 한다. 설명형 랜딩 페이지나 큰 마케팅 히어로는 만들지 않는다.

## 스킴: 다크가 기본, 라이트는 종이 위 잉크

- **다크 + 게임 원본 애셋이 먼저다.** `:root`가 다크 정본이다. 라이트는 `.light`가 **서비스 셸 팔레트 전체**를 종이 배경에 맞게 다시 깐다. 배경만 밝히고 다크용 글자색을 그대로 두지 않는다.
- 방문 기본은 항상 다크다. localStorage에 값이 없으면 **다크**다. 시스템 설정을 기본으로 쓰지 않는다.
- 저장 키는 `sts-color-scheme`. 값: `dark`(기본·권장) / `light` / `system`. `system`만 `prefers-color-scheme`을 따른다.
- 컨트롤은 상단바가 아니라 **프로필** 헤더에 둔다.
- 라이트 셸: 페이지 배경 `#f4f1ea`, 본문 잉크, `--primary` 잉크 골드 `#7a4e0e`(같은 골드 색상, 종이 대비용), `--service-aqua` 잉크 틸 `#0e6b5f`. `zinc-50`/`zinc-100` 같은 다크용 창백한 유틸도 잉크로 재매핑한다.
- 게임 크롬은 `.dark` 섬이다. 카드 아트, hover tip 9-slice, 확인 팝업, 인스펙트 커서, 백과사전 검색창 인셋은 추출 hex(`TEXT_GOLD` `#EFC851` 등)를 유지한다.
- 패치 Worker HTML도 같은 `sts-color-scheme` 부트 스크립트를 쓴다. 요청 시점에 테마를 계산하지 않는다. Storybook 워크숍 캔버스는 다크다.

## 색 층: 게임 텍스트 ≠ 캐릭터 ≠ Tailwind 숫자

같은 영어 색 이름이라도 **층이 다르면 다른 색**이다. `green-500` = `spire-green` = 사일런트 = 버프가 아니다. 그래서 shadcn/`*-nnn`에 `spire-*`를 1:1로 얹지 않는다.

### 1. 게임 텍스트 (`StsColors.cs` → `src/lib/sts2-card-style.ts`)

카드 본문, `[gold]`/`[green]` 태그, hover tip 제목, 버프/너프 숫자. 추출값 그대로 쓴다.

| 토큰 | hex | 쓰는 곳 |
| --- | --- | --- |
| `TEXT_GOLD` | `#EFC851` | 게임 크롬 골드. `[gold]`, hover tip 제목, 다크 `--primary` |
| `TEXT_GREEN` | `#7FFF00` | `[green]`, 강화 수치, 버프 + sine |
| `TEXT_RED` | `#FF5555` | `[red]`, 너프 + jitter |
| `TEXT_BLUE` | `#87CEEB` | `[blue]` 수치/방어도 등 게임 본문 파랑 |
| `TEXT_AQUA` | `#2AEBBE` | `[aqua]`. 서비스 링크 aqua는 라이트에서 `--service-aqua` |
| `TEXT_PURPLE` | `#EE82EE` | `[purple]`, 인챈트 제목 |
| `TEXT_CREAM` | `#FFF6E2` | 카드/팁 본문 크림 |

이 hex들은 Tailwind 팔레트에 없다. `yellow-500`은 프레임워크 기본값이고, 옛 `#d4a843`은 게임 골드가 아니다. **게임 gold 키워드는 `TEXT_GOLD` 하나**다. 라이트 셸의 `--primary`는 그 색을 종이에 올릴 수 있게 같은 색상환에서 잉크로 내린 값이지, 다른 골드 브랜드가 아니다.

Tailwind `500`은 라이트 모드 중심 스케일의 중간이다. 다크가 기본인 이 서비스에서 500을 “다크 기본 강조”로 쓰지 않는다. 다크 강조는 게임 hex, 라이트 강조는 같은 색의 잉크 variant다.

HUD 숫자(히스토리 코스 `topbar-num-gold` `#f8d56a`)는 검정 외곽선 위의 **체력/골드/타이머 페인트**이지 `[gold]`가 아니다. 이 층에 합치지 않는다.

### 2. 캐릭터 정체성 (`CHARACTER_COLORS`)

타이틀·섹션·필터 아이콘 보강에만 제한적으로 쓴다. 지금은 Tailwind 400에 가까운 hex이지만, **정본은 캐릭터 이름이지 `green-400`이 아니다.** 버프 초록(`TEXT_GREEN`)과 사일런트 초록은 다른 색이다.

- 아이언클래드: `#f87171`
- 사일런트: `#34d399`
- 리젠트: `#fb923c`
- 네크로바인더: `#f472b6`
- 디펙트: `#22d3ee`

`.spire-red` / `.spire-green` / … 클래스는 이 캐릭터 층이다. `[red]`/`[green]` 게임 태그에 재사용하지 않는다.

### 3. 막 (비스티어리 구분)

막은 캐릭터도 희귀도도 아니다. 실제 막 이름은 몬스터 도감 `NBestiaryActDivider` 감각의 파란색이다. 게임 본문 `[blue]`(`TEXT_BLUE`)와 섞지 않는다.

- 실제 막 텍스트: `#60a5fa`
- 막 무관: `text-zinc-400`, 점은 `#666`
- 이벤트/고대의 존재/인카운터에서도 막별 green/orange/yellow를 쓰지 않는다.

### 4. 서비스 셸 (shadcn 의미 토큰)

페이지 배경, 패널, 본문/보조 글자, 테두리. 다크 값이 정본이다. `--primary`는 흰 회색이 아니다.

| 용도 | 다크 | 라이트 |
| --- | --- | --- |
| 페이지 배경 | `bg-background` | 종이 `#f4f1ea` |
| 패널/상단바 | `bg-sidebar` (`#16162a` 계열) | 크림 사이드바 |
| 주요 텍스트 | `text-foreground` | 잉크 |
| 기본 강조 / primary | `TEXT_GOLD` `#EFC851` | 잉크 골드 `#7a4e0e` |
| 섀소식·외부 링크 | `TEXT_AQUA` `#2AEBBE` | 잉크 틸 `#0e6b5f` |
| 버프 | `TEXT_GREEN` + sine | 종이 위는 `#1f7a22` |
| 너프 | `TEXT_RED` + jitter | 종이 위는 `#c03636` |

링크 색(게임 리소스 gold / 섀소식·외부 aqua)은 `src/lib/service-link-classes.ts`가 정본이다. Tailwind `cyan-*`는 링크에 쓰지 않는다. 디펙트 `.spire-aqua`와 이거아님저거 왼쪽 투표 크롬은 캐릭터/투표 층이라 링크 aqua(`TEXT_AQUA`)와 다르다.

## 전체 톤

어두운 판타지 UI. 화면은 조용하고 정보 밀도가 높아야 하며, 반복 탐색에 방해되는 과한 장식, 커다란 카드 섹션, 원노트 그라디언트 배경을 피한다.

## 컨테이너와 선택 컨트롤

반복 선택 UI에서 아이템을 담기 위해 필요한 stretch wrapper, grid cell, carousel item은 되도록 컨테이너처럼 보이지 않게 한다.

- 선택 아이콘은 배경 위에 떠 있는 게임 아이콘처럼 보여야 한다. 기본 상태의 카드형 배경, 테두리, 패널 그림자는 피한다.
- 선택 상태는 외곽 박스보다 밝기, 크기, glow, 작은 표시점처럼 아이콘 자체에 가까운 신호로 표현한다.
- 아이콘 아래 고정 라벨은 공간을 늘리고 카드처럼 보이게 만들면 쓰지 않는다. 이름과 보조 정보는 hover affordance로 제공한다.
- 실제 정보를 구획하는 패널이 아니라 정렬만을 위한 컨테이너라면 배경과 경계를 없앤다.
- 우측 preview/render 영역은 여러 칸으로 쪼개기보다 하나의 큰 무대처럼 쓰고, 선택 목록은 필요한 폭만 차지한다.

## 게임 충실도와 웹 차이

게임 원본을 따르는 대상과 웹 서비스라 달라지는 대상을 분리한다.

- 게임 데이터, 공식 명칭/번역, 추출 에셋, 카드/유물/포션/몬스터 같은 리소스의 시각적 정체성은 게임 원본을 우선한다.
- 검색, 필터, URL 공유, 댓글, 좋아요, 패치노트 hover/link, 비교/정렬처럼 게임에 없는 기능은 웹 탐색과 공유를 위해 추가할 수 있다.
- 웹 기능을 추가하더라도 게임 리소스 자체를 일반 카드형 패널 안에 가두지 않는다. 게임에서 경계 없이 떠 있는 요소는 웹에서도 배경 위에 떠 있는 무대처럼 보여준다.
- 게임에 대응되는 컨테이너가 없는 추가 정보는 게임 에셋보다 덜 두드러지는 보조 패널, 하단 영역, 사이드 영역으로 분리한다.
- 게임과 다른 표현은 “웹에서 찾고 비교하고 공유하기 위해서”만 허용하며, 새 장식 체계나 임의의 판타지 UI를 만들기 위한 이유로 쓰지 않는다.

## 호버 팁 — 둘은 용도가 달라 각각 둔다

같은 `hover_tip.png` 9-slice를 쓰지만 **화면에서의 역할이 다르다.** 하나로 합치지 않는다.

- `GameHoverTip`: 카드/유물/포션처럼 **이름 + 효과 설명**(필요하면 아이콘·아트)을 보여주는 게임 툴팁. 인라인으로 붙는다.
- `GameUiHoverTip`: 내비, 좋아요, 댓글처럼 **아이콘 한 줄 라벨**. `document.body`로 포탈해서 잘리지 않게 한다.

코드에서만 9-slice 숫자(게임 `hover_tip.tscn`의 43/91/32/55)와 제목색 `TEXT_GOLD`를 공유한다. 셸·배치·본문 슬롯은 각자의 컴포넌트에 남긴다.

`GameConfirmModal`(추출한 예/아니오 팝업)은 서비스 글쓰기 모달과 층이 다르다. 합치지 않는다.

## 좋아요 — 강령의 극의 하나

백과사전·장난감 상자에서 보이는 좋아요는 `SpireLikeIcon`(`necro_mastery_power.webp`, 강령의 극의)이다. 유휴는 ghost wax, 호버/활성은 `TEXT_GOLD`.

- 이야기 8감정 팔레트는 운영에서 깨질 수 있어 **이번에는 바꾸지 않는다.** 백과사전 타일·상세 좋아요만 강령의 극 스킨이다. `reaction_type` 컬럼은 그대로 둔다.
- 장난감 상자(코옴보/변형/케미컬X/조각모음)와 백과사전·패치 스레드는 이미 공유 `likes` 테이블이다.
- 이거아님저거는 **보이는 버튼은 같다.** `this_or_that_post_likes` 테이블은 그대로 둔다. 투표용 엄지(`thumb_up`/`thumb_down` 석판)는 좋아요가 아니다.
- 댓글 좋아요는 `comment_likes`를 유지하되 크롬만 `LikeControl`이다.
- STS1 `CharacterBadge` / shadcn `Badge`는 **deprecated**. STS1 레거시 화면에만 두고, 새 UI에 쓰지 않는다. 나중에 백과사전 캐릭터 표시와 통합할 수는 있으나 지금은 기술부채로 남긴다.

## 백과사전 공통 레이아웃

카드, 유물, 포션, 파워, 인챈트, 몬스터, 인카운터, 이벤트, 고대의 존재 목록은 가능한 한 백과사전 공통 셸과 상단바를 공유한다.

- 좌측 필터 드로어는 데스크톱에서 고정 폭으로 열리고, 모바일에서는 필터 버튼으로 열리는 drawer로 동작한다.
- 상단바는 필터 토글, 짧은 제목, 중앙 검색창, 결과 수, 필요 시 버전 선택기를 포함한다.
- 목록 본문은 상단바 아래에서 독립 스크롤된다.
- 큰 페이지 제목 블록은 백과사전 목록 화면에 쓰지 않는다.
- 검색창은 각 화면의 주요 탐색 도구이며 `Cmd/Ctrl+K`로 포커스한다.
- 필터 trigger 표기는 검색 토큰과 맞춘다: `@` 캐릭터/소속, `#` 유형, `$` 희귀도, `!` 비용, `%` 막.

## 공통 컴포넌트 용어

- `CompendiumIndexLayout`: 좌측 필터, 상단바, 목록 본문을 묶는 백과사전 인덱스 공통 레이아웃. 옛 이름 `CodexLibraryShell`은 별칭만 남긴다.
- `CompendiumIndexTopBar`: 검색창, 필터 버튼, 결과 수, 버전 선택기를 담는 백과사전 인덱스 상단바. 옛 이름 `CodexLibraryTopBar`는 별칭만 남긴다.
- `GameHoverTip` / `GameUiHoverTip`: 위 호버 팁 절.
- `RelatedResourceLinks`: 관련 리소스 라인을 렌더한다. 옛 이름 `EntityReferenceGroupLinks`는 별칭만 남긴다.
- `ResourceDetailView`: 카드, 유물, 포션 같은 리소스의 상세 보기를 렌더하는 표준 컴포넌트명이다. 모달과 직접 URL 진입에서 같은 상세 보기를 공유한다.
- `LikeControl` / `LikeButton`: 좋아요 크롬과 `likes` 테이블 훅. 이거아님저거 테이블이 남는 동안만 별도 훅을 둔다.

## 목록 화면

### 카드

- 카드 이미지를 중심으로 grid를 구성한다.
- 캐릭터, 유형, 희귀도, 비용, 이름 정렬을 좌측 필터에서 제공한다.
- 기본/일반/고급/희귀 외 특수 카드군은 "기타" 하위 필터로 정리한다.
- 업그레이드, 베타 아트, 멀티플레이어 카드, 댓글/좋아요 표시는 명시 토글로 둔다.

### 유물

- 작은 유물 아이콘 grid를 유지한다.
- 희귀도 단위로 섹션을 나누고, 고대 유물은 고대의 존재별 하위 그룹을 보여준다.
- 이벤트 유물은 소속 필터에서 별도로 고를 수 있어야 한다.
- 상세 보기의 주 무대는 카드형 컨테이너가 아니라 떠 있는 유물 아이콘과 게임 hover tip 감각의 이름/설명으로 구성한다.
- 목록 hover와 상세 보기의 툴팁은 임의의 웹 카드가 아니라 게임에서 물약/유물에 쓰는 hover tip 애셋 감각을 따른다.
- 유물 상세 보기의 데스크톱 주 무대는 게임 hover처럼 아이콘 옆에 `GameHoverTip`이 붙는 배치를 기준으로 한다. 포션 선택 UI처럼 툴팁이 아래에 놓이는 사례보다 카드/유물 hover 감각을 우선한다.
- 유물 `GameHoverTip`에는 유물 이름과 게임 효과 설명만 담는다. 영문명, 희귀도, 소스 같은 서비스 메타는 정보 레일로 보낸다.

### 포션

- 포션 아이콘 중심 grid를 유지한다.
- 일반/고급/희귀/특별 섹션으로 묶는다.
- 캐릭터/공용/이벤트 pool 필터를 제공한다.

### 파워와 인챈트

- 파워는 Buff/Debuff/Other처럼 게임 내 역할을 기준으로 묶는다.
- 인챈트는 적용 카드 유형과 중첩 가능 여부가 핵심 필터다.
- 설명 텍스트에는 rich description 렌더링과 cross-reference를 유지한다.

### 몬스터

- 게임 구현 기준: `NBestiary.AddAct()`처럼 막 구분자를 먼저 두고, 각 막 안에서 일반 전투, 엘리트, 보스, 이름순으로 정렬한다.
- 막 제목은 `#60a5fa` 파란색으로 표시한다.
- 몬스터 이름/유형은 게임의 `NBestiaryEntry` 감각에 맞춰 일반 몬스터 cream/white, 엘리트 purple, 보스 red를 유지한다.
- 상세 화면의 행동은 시작점이 있는 상태 전이표로 보여준다. 명시적인 `__START__` 전이가 있으면 그대로 쓰고, 없으면 `move_graph.initial`을 시작점으로 보강한다.
- 행동 미리보기 목록은 게임의 `MonsterModel.GenerateBestiaryMoveList()` 기준을 따른다.

### 인카운터

- 막과 전투 유형이 핵심 필터다.
- 몬스터 상세와 인카운터 상세는 양방향 탐색 가능해야 한다.
- encounter 원본의 조합 분기가 아직 평탄화된 경우, UI에서 확정 조합처럼 표현하지 않는다.

### 이벤트

- 백과사전 공통 셸을 사용한다.
- 좌측 막 필터와 섹션 제목은 몬스터 도감과 같은 파란 막 스타일을 쓴다.
- 목록 항목은 이벤트 이미지를 낮은 대비 배경으로 깔고, 한국어 이름과 영어 원문을 함께 표시한다.
- 클릭 시 상세 모달을 열고, URL query에 선택 이벤트를 반영한다.

### 고대의 존재

- 백과사전 공통 셸을 사용한다.
- 막 필터와 섹션 제목은 이벤트와 동일한 파란 막 스타일을 쓴다.
- 카드는 고대의 존재 이미지, 이름, 영어명, 이명, 등장 막, 보상 유물 수를 보여준다.
- 고대의 존재 자체는 blue 계열 정체성을 유지하되, 개별 리소스 링크/강조가 필요할 때는 rich text의 gold 링크 규칙을 따른다.

## 상세 화면

- 항목의 상세는 모달과 상세 페이지로 깊이를 나누지 않는 하나의 상세 보기다.
- 목록에서 항목을 클릭하면 대체로 모달 표현을 우선하고, 직접 URL로 들어오면 같은 상세 보기를 주소 가능한 페이지로 렌더한다.
- 모달은 웹 서비스의 탐색 기능이지만, 상세 보기 안의 주 리소스 표현은 게임식 화면을 우선한다.
- 카드 도서관처럼 게임에서 카드가 컨테이너나 경계선 없이 떠 있는 경우, 카드 상세도 카드 자체를 배경 위에 띄우고 불필요한 카드형 wrapper를 만들지 않는다.
- 상세 보기는 배경 dim + blur, Escape, 바깥 클릭 같은 모달 동작을 지원하되, 직접 URL 진입에서는 같은 정보를 별도 2-depth 없이 보여준다.
- 게임에 없지만 서비스에 필요한 추가 정보는 같은 상세 보기 안의 접을 수 있는 정보 레일에 둔다. 댓글, 관련 리소스, 패치 이력, 내부 메타데이터처럼 탐색을 돕는 정보도 별도 페이지 전용 정보가 되면 안 된다.
- 정보 레일은 데스크톱에서 주 리소스 옆에, 모바일에서 주 리소스 아래에 배치한다.
- 정보 레일은 주 리소스보다 시각적으로 앞서면 안 되며, 정보량이 길어질 때는 같은 상세 보기 안에서 접힘, 탭, 섹션으로 정리한다.
- 정보 레일의 기본 섹션은 관련 리소스, 댓글, 패치 이력이다.
- 패치 이력은 수치, 텍스트, 등장 여부처럼 현재 리소스가 실제로 바뀐 구조화 변경만 보여준다. Rich 패치 본문에서 이름이 언급된 기록은 패치 이력에 섞지 않는다.
- 관련 리소스 레일은 Rich 패치의 hover/link 아이디어를 백과사전 상세에 확장한 것이다. 카드, 유물, 포션, 이벤트 같은 리소스를 정방향/역방향으로 촘촘히 연결하되, 게임 툴팁 자체와 섞지 않는다.
- 관련 리소스는 리소스 종류별 독립 카드 섹션을 만들기보다 하나의 섹션 안에 `관련 카드: ...`, `관련 유물: ...`, `관련 포션: ...` 같은 라인을 쌓는다.
- 관련 리소스 라인은 접힘 UI가 아니라 키워드 링크 나열이다. 항목이 너무 많을 때는 같은 줄 안에서 줄임 처리하거나 더보기 affordance를 둔다.
- 상세 보기 시안은 카드 도서관의 floating card를 기준점으로 삼되, 첫 비카드 검증 대상은 유물로 한다. 유물은 게임에 독립 상세 화면이 없어서 서비스가 추가 정보를 어떻게 품는지 검증하기 좋다.
- 상세 내 cross-reference는 hover preview와 클릭 이동을 제공한다.
- 긴 설명과 선택지는 게임 텍스트의 줄바꿈/강조를 살리되, 화면 폭에 맞게 읽히도록 한다.

## Rich Patch Notes

Rich 패치는 Steam 패치노트를 소스로 하되, 백과사전 데이터와 연결되는 서비스 콘텐츠다.

- 기본 게임 요소 강조는 `TEXT_GOLD`다.
- hover 시 해당 카드/유물/포션/파워/몬스터/이벤트/고대의 존재를 렌더한다.
- 클릭 시 가능한 경우 해당 백과사전 리소스로 이동한다.
- 버프는 `TEXT_GREEN` + sine, 너프는 `TEXT_RED` + jitter를 사용한다.
- 특정 게임 요소 이름은 현재 PCK/백과사전 데이터의 공식 한국어명을 사용한다.

## 반응형 규칙

- 데스크톱: 좌측 필터를 열어 둔 상태가 기본이다.
- 모바일: 필터는 drawer로 열고, 본문 스크롤을 방해하지 않는다.
- 상단바 텍스트와 검색창은 한 줄 안에서 겹치지 않아야 한다.
- 카드/타일/아이콘 grid는 고정 폭 또는 안정적인 responsive track을 사용해 hover/로딩/카운트 표시가 레이아웃을 흔들지 않게 한다.

## 정렬 로드맵

라이트모드는 서비스 셸 variant다. 게임 크롬은 스킴에 묶지 않는다.

1. **정본 문서** — 이 파일. Storybook은 문서를 그린다. 완료.
2. **게임 텍스트 토큰 + `:root` 다크** — `.spire-gold`/`--primary` = `TEXT_GOLD`. `[green]`/`[red]`/`[blue]` 등은 `StsColors`. `:root`가 다크 정본. 완료.
3. **서비스 셸의 `yellow-500` / `#d4a843` 잔여** — 강조는 `--primary` / `TEXT_GOLD`. 완료. 3막 영광 칩과 통합검색 유물 타입 칩은 골드 강조가 아니라서 그대로 둔다.
4. **링크 색** — 게임 리소스 gold, 섀소식·외부 aqua. `cyan-*` 링크 유틸 제거. 완료.
5. **좋아요** — 백과사전 타일 스킨은 강령의 극. 이야기 감정 팔레트는 prod에서 깨질 수 있어 보류. 이거아님저거 테이블은 병합하지 않는다.
6. **이름 정리** — 호출부 `CompendiumIndexLayout` / `RelatedResourceLinks`. 완료. 통합검색 라벨은 인챈트.
7. **라이트 variant** — 서비스 셸 팔레트(잉크 골드/틸). 프로필 `sts-color-scheme`. 패치 Worker도 같은 키를 읽는다. 게임 크롬은 `.dark` 섬. Storybook 캔버스는 다크. 완료.

## 아직 손대지 않는 것들 (사람말로)

이전에 “같은 의도인데 분기” / “복붙·지엽”이라고 적어 둔 목록이다. 합치라는 뜻이 아니라, **겉보기만 비슷해서 나중에 헷갈리지 말라는 메모**다.

- **장난감 상자 글 카드 네 종류**는 가운데에 들어가는 그림이 다르다. 코옴보는 카드 더미, 이거아님저거는 양쪽 선택, 변형은 미리보기. 위쪽 닉네임·시간·좋아요만 비슷하다. 껍데기만 나중에 묶을 수 있고, 지금 한 컴포넌트로 억지로 합치면 본문 분기가 숨는다.
- **이거아님저거 카드 아랫줄**은 좋아요 옆에 투표가 있어서, 다른 서비스의 “댓글+좋아요” 묶음(`IndexCardEngagement`)을 그대로 못 쓴다.
- **리소스 고르는 창**도 검색창은 닮았지만, 코옴보는 여러 장, 변형은 타입 제한, 이거아님저거는 한쪽 칸이다. 고르는 규칙이 달라 창 전체를 하나로 합치지 않는다.
- **백과사전에서 항목을 열 때 뒤에 깔리는 어두운 막**은 같은 CSS가 여러 파일에 복사돼 있다. 상세 보기 공통 스크림으로 모을 후보다.
- **이야기 쓰기 창**은 아직 장난감 상자 글쓰기 공통 프레임(`ServiceModalFrame`)을 안 쓴다. 케미컬X는 목록에서 바로 써서 창이 없다. 제품이 달라서다.
- **STS1 카드/유물/포션 브라우저**는 옛 사이트다. 백과사전 셸과 합치지 않는다.
- **통합검색과 백과사전의 인챈트**는 같은 게임 용어다. 검색 라벨도 인챈트다.
- **`/dev/text-effects`, `/dev/spire-icons`**는 개발자 견본이다. Storybook이 정본 견본이다.

## 남은 디자인 과제

- 몬스터 인덱스를 게임처럼 긴 텍스트 목록으로 갈지, 현재처럼 이미지/이름 중심의 도감 목록으로 유지할지 결정이 필요하다.
- 몬스터 상세는 Spine 렌더가 배경에 떠 있는 듯한 비스티어리식 화면으로 옮기는 별도 시안이 필요하다.
- 정보 레일의 기본 접힘/펼침 상태는 전체 규칙으로 확정하지 않고, 카드/유물/포션/몬스터 같은 실제 리소스 종류별 mockup을 본 뒤 결정한다.
- 인카운터 조합은 `GenerateMonsters()` 분기와 확률/동등 선택 여부를 구조화하면 더 정확하게 보여줄 수 있다.
- Spine/VFX 표시 옵션은 미완성, mimic, static-only, 파싱 실패 상태를 토글 가능한 메타데이터로 분리한다.
