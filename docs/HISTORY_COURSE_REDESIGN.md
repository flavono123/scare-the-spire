# 역사 강의서 개편안

슬레이 더 스파이어 커뮤니티가 런을 공유할 때 쓰는 **중괄호형 유튜브 썸네일 문법**을 인덱스·코오오옴보 참조 표지로 옮긴다. AI 판정·추천 피드·조합 사전 운영은 하지 않는다.

학습 스크랩·공출현 덤프(`*.json` / `*.jsonl`)는 gitignore된 [`research/history-course-covers/`](../research/history-course-covers/)에 둔다. 문구·요소 조합 스펙 SSOT는 [`research/history-course-covers/LOGIC.md`](../research/history-course-covers/LOGIC.md), 관찰 노트는 [`patterns.md`](../research/history-course-covers/patterns.md).

## 세 축

| # | 축 | 상태 |
| --- | --- | --- |
| 1 | 인덱스(+ 코오오옴보 참조)에서 보이는 **유튜브형 표지** | **진행 중** |
| 2 | 상세 리플레이 시 **재미 증대** | **진행 중** |
| 3 | 상세 리플레이 시 **복기 기능 강화** | 이후 (층 멘션·hover는 일부 적용됨) |

축 1 표지 문법은 유지한다. 축 2는 맵에 머무는 슬롯머신 보상 스택을, 노드 마지막 씬 루프로 바꾼다.

## 축 1 — 표지

### 문법 (3층)

1. **배경 아트**
2. **도전 이력의 핵심 문구** (한 줄)
3. **핵심 게임 요소 1–3** (카드·유물·포션 등; 같은 타입·같은 카드 반복 허용)

참고 문법: 원인 쪽 `{ 카드·유물 }` + 결과 한 줄(`∞` / 큰 숫자 / “보통 X가 아니다”). 슬갤·중괄호 계열 제목에서 반복되는 패턴이며, 표본 URL은 `research/history-course-covers/sources.md`에 둔다.

### 업로드 시 후보 2안

배경만 갈라진 두 인덱스를 제안하고, **1번을 자동 저장**한다.

| 안 | 배경 | 요소 |
| --- | --- | --- |
| 1 (기본) | 런 캐릭터 아트 | 가중 랜덤 1–3 |
| 2 | 핵심 카드의 베타 아트 (`cards-beta/`, 없으면 정식 `cards/`) | 같은 풀에서 뽑되 **배경 카드 id는 요소에 넣지 않음** |

문구·요소는 **런 내 가중 + 정적 콤보 공출현 테이블**로 뽑는다. 트렌드 AI·수동 메타 매핑은 쓰지 않는다. 유저가 문구/요소/배경을 바꾸거나 “다시 섞기” 할 수 있다. 안 건드려도 인덱스는 예쁘게 나와야 한다.

### 시각

- 폰트: 사이트 locale 폰트(`.font-game-title` 등). 중괄호 전용 폰트 미도입.
- 외곽: 흰 굵은 outline 정도만 참고.
- 색: [`.spire-*`](../src/app/globals.css) — 캐릭터 필은 캐릭터색, 요소 강조는 `spire-gold`.
- 렌더: 이미지 생성물 아님. 기존 webp를 조립한 DOM(`aspect-video`). Cloudflare Worker에서 파싱·이미지 작업 없음.
- 재사용: 역사 강의서 인덱스와 코오오옴보의 history-run 참조가 같은 표지 컴포넌트를 쓴다.

### 저장 (구현 시)

가칭 `cover_spec` jsonb. 인덱스는 raw `.run`을 다시 파싱하지 않고 표지 스펙만 읽는다. 상세는 [`LOGIC.md`](../research/history-course-covers/LOGIC.md).

### 하지 않음 (축 1)

AI 분석/생성, 자동 하이라이트 점수, 지속 갱신 휴리스틱 사전, 동적 OG 이미지, Worker 런타임 이미지 렌더, 추천 피드.

### 성공 지표 (축 1)

- 공개 런의 상세 진입률
- (선택) 자동 표지 대비 커스텀 표지 비율

## 축 2 — 상세 리플레이 재미

표지가 약속한 “왜 볼지”가 재생 중에도 끊기지 않게 하는 축. 구현 핵심은 **노드마다 결과+선택지만** 보여 주고, 하이라이트처럼 빠르게 다음 노드로 가는 것이다.

현재 상세는 16:9 맵에 머문 채 `NodeActionStack`(슬롯머신/룰렛)으로 보상 아이콘을 흘린다. 축 2는 그 스택을 메인 연출로 쓰지 않는다. 화면이 전환되므로 스택 코드는 휴식처·미구현 씬의 폴백으로 남겨도 된다.

### 루프

```text
맵에서 다음 노드 선택(기존 Phase 4 경로 페인트 + 캐릭터 도착)
  → 해당 노드의 마지막 씬
  → 맵으로 돌아와 다음 노드 선택
```

| 노드 | 마지막 씬 | `.run`에서 쓰는 것 |
| --- | --- | --- |
| 일반/엘리트/보스 | 맵 몹이 전부 죽는 연출 → 카드·유물·포션 보상 선택 | `rooms[].monster_ids`, `model_id`, `card_choices` / `relic_choices` / `potion_choices`, `cards_gained` |
| 상점 | 구매·제거하는 모습 | `bought_*`, `gold_spent`, `card_choices`(미구매 진열), `cards_removed` |
| 이벤트/미지 이벤트 | 선택지를 고르는 모습 | `rooms[].model_id`, `event_choices`(+ loc vars), 부가 `upgraded_cards` / `cards_transformed` |
| 보물 | 게임과 같은 상자 연출 | `relic_choices`, `gold_gained` |
| 휴식처 | 휴식/강화/점화 선택 | `rest_site_choices`, `upgraded_cards`, `hp_healed` |
| 고대 | 축복 선택 | `ancient_choice` |
| 사망 노드 | 사망 연출 | `current_hp === 0`, 런 최상위 `killed_by_encounter` / `was_abandoned` |

전투 **중** 카드 플레이·에너지·의도·몹 HP 곡선은 `.run`에 없다. 지어내지 않는다. 축 3과 같은 제약이다.

### 레퍼런스

제품 SSOT는 위 루프다. 모카계 채널에 한때 있던 **맵 선택 → 노드 마지막 씬 → 맵** 컷 영상은 내린 것으로 보고, 공개 스피드런을 그 자리의 대용 레퍼런스로 쓰지 않는다. 스피드런은 전투 APM이 본편이라 축 2와 형식이 다르다.

### 타이밍

지금 타임라인은 노드마다 `NODE_BASE_MS(2500)` + 스택 아이템 × `2500ms`다. 상점처럼 아이템이 많으면 하이라이트가 아니라 대기열이 된다. 축 2는 아이템 개수에 비례하지 않는다.

| 구간 | 권장 | 비고 |
| --- | --- | --- |
| 맵 트랜짓 (Phase 4) | 기존 `NODE_BASE_MS` 유지 | 경로 페인트 + 캐릭터 도착 |
| 일상 마지막 씬 | 약 1.2–2.0s 고정 | 몹 사망 한 컷 + 선택 1회 연출 |
| 하이라이트 노드 | 약 3–4s | 선택지와 결과를 한 화면에 더 오래 |
| 막 사이 | 기존 `ACT_TAIL_BUFFER_MS` | 인트로와 겹치지 않게 |

50층 × (2.5s 맵 + ~1.6s 씬) ≈ 3.5분. 하이라이트 몇 개만 늘린다. 슬롯머신 대기열을 재생 길이의 SSOT로 쓰지 않는다.

### `.run`에 있고 마지막 씬 **외에** 쓸 수 있는 것

로컬 Steam 히스토리 103판. 방 키는 `room_type` / `model_id` / `turns_taken` / `monster_ids`뿐. `parseReplayRun`은 `rooms[].monster_ids`와 최상위 `killed_by_encounter` / `killed_by_event` / `was_abandoned`를 통과시킨다. 승리는 `NONE.NONE` → `null`.

마지막 씬(선택·획득 연출)과 **겹치지 않는** 활용:

| 데이터 | 어디에 쓰나 |
| --- | --- |
| `rooms[].monster_ids` | 전투 마지막 씬의 몹 라인업(사망 연출). 맵 아이콘만으로 때우지 않음 |
| `rooms[].turns_taken`, `damage_taken` | 전투를 안 보여 줘도 “몇 턴·받은 피해”는 HUD/hover에 사실로 남김 |
| `killed_by_encounter` / `killed_by_event` | 사망 씬 원인. 승리는 `NONE.NONE` |
| `was_abandoned` | 포기 vs 사망 구분 |
| `current_hp` / `max_hp` / 골드 4종 / `stolen_loot` | 상단바·맵 hover. 상점 씬의 잔여 골드 |
| `was_picked: false` 진열 | 고르지 않은 보상·상점 재고. “못 산 텐트”의 조건 쪽 |
| `unknown` → `rooms[0].room_type` | 미지가 전투였는지 이벤트였는지. 로컬 114 전투 / 473 이벤트 |
| `potion_used` / `potion_discarded` | 전투 로그 없이 포션 소비만 표시(535층에 사용 기록) |
| `player_stats[]` | 파티 도난·각자 선택. 슬갤 폴짝이 스틸류 |
| 엔드 `players[].relics.props` / `deck.props` | 점화 횟수, 사신의 낫 누적, 마과학 변형. 큰 숫자 주장의 **허용된** 출처 |
| 시드 재구성 맵, 배지, 수정자 | 이미 맵이 씀. 하이라이트 점수로 쓰지 않음 |

없는 것(하이라이트 카피에 쓰지 말 것): 전투 중 딜·에너지·의도·몹 HP 곡선, 상점 **가격**. 진열+잔여 골드만으로는 “1원 모자람”을 단정할 수 없다. 가격을 시드로 재구성하기 전에는 “못 사고 골드 N 남음” / “사고 골드 N 남음”까지만.

### 하이라이트 휴리스틱

축 1의 “자동 하이라이트 점수 / AI” 금지는 **표지 문구**에 대한 것이다. 축 2는 재생 중 **같은 조건·반대 결과**가 한 화면에 보이는 층을 더 오래 보여 준다. 슬갤이 캡쳐하는 단위는 전투 리플레이가 아니라 그 한 화면이다.

핵심 패턴은 사용자 예시와 같다. 출진 물감·강화 이벤트가 타격/수비만 때리는 판과 핵심 스킬을 때리는 판, 텐트를 딱돈에 산 판과 1원 모자라 못 산 판. 조건은 같고 결과만 갈린다. 로컬 표본: 출진 물감+같은 층 강화 11건 중 수비만 2장 강화 3건 vs `ESCAPE_PLAN`+`DEADLY_POISON` 같은 비스타터. 텐트 상점 8건 중 구매 4 / 미구매 4, 잔여 골드 0·15·34 vs 13·59.

| 유형 | 슬갤에서 보이는 형태 | JSON으로 재구성 |
| --- | --- | --- |
| 무작위 강화의 양면 | 출진 물감·강화 이벤트가 타격/수비만 vs 핵심 스킬 | 가능. `WAR_PAINT` 획득 층 `upgraded_cards`가 `STRIKE_`/`DEFEND_`인지 |
| 상점 잔여 골드 | 텐트 딱돈 vs 1원 모자람 | 부분. `MINIATURE_TENT` + `was_picked` + `current_gold`. 가격 재구성 전엔 N원 잔여만 |
| 아이러니 사망 | 75 HP 들고 사망, 휴식처가 전부 열린 뒤 빨간 배경 | 가능. [불운 사망](https://gall.dcinside.com/mgallery/board/view/?id=slay&no=375190), [레전드 휴식](https://gall.dcinside.com/mgallery/board/view/?id=slay&no=374279) |
| 한 화면 도박 | 라이터 사고 시너지 | 가능. [라이터 도박](https://gall.dcinside.com/mgallery/board/view/?id=slay&no=478799) — 상점 `bought_relics` |
| 경로 불운 | 3막 미지가 전부 전투, 유물 타기 | 가능. [3막 미지](https://gall.dcinside.com/mgallery/board/view/?id=slay&no=478742) — `unknown`→`room_type` 연속 |
| 큰 숫자/무한 | 억 딜, 0코 루프 | **전투 딜은 없음.** 덱 매수, 유물 개수, props 카운터만 |
| 스킵 | 엘리트/보스 카드 보상 전부 스킵 | 가능. 로컬 523층에서 `card_choices` 전부 미선택 |
| 파티 스틸 | 폴짝이가 오브 훔침 | 가능. `gold_stolen` / `stolen_loot` / `player_stats[]` (13층) |

요구사항:

- 하이라이트는 **템플릿 태그**다. 점수·리더보드·추천 피드가 아니다.
- 재생바 마커는 기존 층 댓글(`#`) 마커와 **모양이 달라야** 한다.
- 자동 재생은 태그된 노드만 dwell을 늘린다. 일상 노드는 짧게.
- 카피는 재구성 가능한 사실만. “1원 모자람”은 가격 SSOT가 생긴 뒤에만.

### 구현 순서

1. **파서:** `rooms[].monster_ids`, `killed_by_*`, `was_abandoned`를 `ReplayRun`에 통과시킨다. Worker에서 `.run`을 파싱하지 않는다.
2. **씬 라우터:** `map_point_type` / `rooms[0].room_type` / HP0으로 last-scene 종류를 고른다. 맵 트랜짓은 유지. 전용 씬이 뜨는 동안 `NodeActionStack`은 숨긴다. 휴식처·미구현은 스택을 폴백으로 둔다.
3. **전투 마지막 씬:** `monster_ids` 라인업이 죽는 연출(도감 Spine/정지 컷) → `card_choices` / `relic_choices` / `potion_choices`를 고르는 모습. 카드 플레이는 없다.
4. **상점·이벤트·보물·사망:** 구매/선택지/상자/사망 이벤트. 보물은 게임 상자 연출을 추출 애셋으로 맞춘다.
5. **하이라이트 태그 + dwell + 재생바 마커.** 축 3 층 멘션과 공존하되 씬 위에 훈수 대시보드를 올리지 않는다.
6. **(선택)** 시드로 상점 가격을 재구성해 “1원 모자람”을 사실로 만든다. 1–5와 묶지 않는다.

Cloudflare Free: 기존 `/history-course/[id]` 정적 셸 + 브라우저에서만 씬. 요청 타임 `.run` 파싱·이미지 작업·검색 인덱스 없음.

### 권장 결정

| 결정 | 권장 |
| --- | --- |
| 룰렛 | 코드는 남긴다. 전용 마지막 씬과 동시에 켜지지는 않는다 |
| 하이라이트 | 마커 + 자동 dwell. 유저가 하이라이트만 점프할 수 있게 |
| 상점 가격 | 1차 범위 밖. 잔여 골드만 보여 준다 |

### 하지 않음 (축 2)

전투 로그 발명, RunReplays 모드 의존, Worker에서 `.run` 파싱/씬 렌더, 표지용 AI 점수와 재생 휴리스틱을 한 모델로 섞기, 모든 노드를 같은 길이로 두기.

### 성공 지표 (축 2)

- 상세 페이지 평균 시청 시간 / 재생 완료율
- 하이라이트 마커 클릭 비율 (층 댓글 마커와 분리 집계)

## 축 3 — 복기 기능 강화 (이후)

층별 관측값·댓글 동선 등. `.run`에 없는 전투 중 상세를 지어내지 않는 제약은 유지한다. 축 2의 마지막 씬은 축 3 hover/층 멘션과 같은 사실을 보여 주되, 훈수용 대시보드를 씬 위에 올리지 않는다.
