# 상단바·네비·통합검색·슬서운 이야기 개편

* **Author:** flavono123
* **Date:** 2026-11-20
* **근거 자료:** [usage_metrics.md](./usage_metrics.md) (Cloudflare 방문 지표와 운영 D1 글 수, 최근 30일과 90일)

## Overview

상단바에는 처음부터 다섯 가지만 보인다: 브랜드, 패치노트, 검색, 프로필, 큰 패널 버튼. 나머지는 모두 큰 패널 하나로 옮긴다.

- **패널 안:** 백과사전(STS1·STS2), 장난감 상자, 짜퍼.
- **짜퍼:** 장난감 상자와 같은 높이의 게임 브랜드가 되고, 커넥션스와 베타 퀴즈부터 하위 게임을 붙인다.
- **활동이 적은 장난감 상자 서비스:** 지우지 않고 더보기 뒤로 접는다.
- **언어:** 프로필 안으로 들어간다.
- **우편함:** PC에서도 하단 떠 있는 버튼이 된다.

통합검색은 게임 요소, 서비스, 백과사전 인덱스를 함께 찾는다. 이름이 정확히 일치하면 항상 맨 위에 온다.

슬서운 이야기는 홈의 `/#id` 모달에서 별도 상세 경로로 옮겨, 뒤로 가기와 공유가 되게 한다. 이야기가 참조하는 게임 요소의 기존 그림을 목록과 상세에 보여 준다.

**개발자 쪽 목표:** 짜퍼 게임을 하나 추가할 때 등록부(registry) 항목 하나와 게임 페이지만 만들면 패널과 검색에 바로 나오게 하는 것.

## Analysis

### 지표가 말하는 것

- **패치노트:** 네비로 들어오는 서비스 중 1위다. 한국어 6,849회로, 한국어 백과사전 목록 3,669회의 거의 두 배다. 백과사전 합계는 더 크지만 외국어 경로와 상세 페이지의 크롤러성 트래픽이 많다.
- **짜퍼:** 연 지 30일 안에 장난감 상자 방문의 57%를 차지한다. 플레이 659건에 73명이 했다. 같은 기간 사이트 전체에서 글을 쓴 사람(30명)보다 많다. 브랜드로 올리는 판단을 지표가 받쳐 준다.
- **홈:** 홈만 방문이 줄었다(−43%). 원인은 이 자료로 알 수 없다.
- **메뉴 클릭:** 기록이 없다. 작성자 판단으로 이번에는 재지 않는다. 이번 개편은 지표 개선이 목표가 아니라, 짜퍼 게임을 쉽게 늘리고 노출하는 공급자 주도 개편이다.
- **외국어 트래픽:** 대부분 크롤러로 본다. 언어는 OS·기기 언어에 맞춰 이미 내려 주고 있으므로, 언어 선택을 프로필 안으로 옮기는 데 따로 대책을 두지 않는다.

### 리뷰에서 나온 큰 위험 (심각한 순)

1. **Supabase 이관은 막힘이 아니다 (리뷰 정정).** 리뷰는 [SUPABASE_EXIT_PARALLEL_WORK.md](docs/SUPABASE_EXIT_PARALLEL_WORK.md)의 "지금 단계"(6단계)를 근거로 막힘이라고 했다. 그런데 이 칸이 오래된 것이다. 실제로는 2026-11-19에 7단계(Supabase 퇴역)로 전환했고([history/2026-11-09.md](docs/release/history/2026-11-09.md) 173행), 남은 것은 7단계 코드 정리뿐이다. 클릭 기록도 범위에서 빠져서 새 테이블이 필요 없다. 정리 작업이 `site-navbar.tsx`를 건드리는지만 확인하고 순서를 맞추면 된다.

2. **패치 페이지가 상단바와 검색을 따로 들고 있다 (막힘).**
   - 패치 Worker 빌드(`scripts/build-patch-worker.tsx:365`의 `StaticPatchHeader`)는 상단바를 다시 그린다.
   - `src/components/patches/patch-global-search-client.ts`는 검색 순위와 "묶음당 8개" 자르기를 복사해 쓴다.
   - 이미 어긋났다. 패치 쪽 STS1 링크는 옛 `/cards`를 가리킨다.

   가장 많이 찾는 패치노트에서 새 네비와 새 검색이 빠지지 않게 하려면, 순위 계산을 공유 함수 하나로 모으고 두 상단바가 같은 등록부를 읽어야 한다.

3. **같은 장소를 설명하는 목록이 일곱 군데로 나뉘어 있다 (막힘: "항목 하나로 추가" 목표).**
   - 네비 항목(`site-nav-items.ts`)
   - 새 글 표시(`nav-seen.ts`)
   - 검색의 서비스 항목(`search-index-data.ts`)과 검색 종류·스타일(`global-search.ts`)
   - 백과사전 인덱스(`_codex/page.tsx`, 카드 수를 손으로 적어 둠)
   - 짜퍼 탭(`vexing-puzzlebox-shell.tsx`)
   - Worker 라우트(`workers/static-page-routing.ts`)
   - 복사 스크립트(`scripts/copy-cf-static-pages.mjs`)

   검색에는 케미컬X, 코오오옴보, 조각모음, 변형이 아예 없다. 복사 스크립트가 `.mjs`이므로 등록부는 JSON(또는 `.mjs`)이어야 한다. 아니면 목록끼리 어긋나는 것을 테스트로 막아야 한다.

4. **정적 파일 예산 (참고).** 새 라우트는 로케일 14개 × HTML·RSC라서 하나에 파일 28개가 든다([CLOUDFLARE_LIMITS.md](docs/CLOUDFLARE_LIMITS.md) 46~49행). 짜퍼 게임 탭도 라우트라서 28개에 그 게임 그림이 더해진다. 2026-11-20 `pnpm cf:limits` 기준 main은 16,464 / 19,500이고, 3,036개가 남았다. 게임을 늘리는 것 자체는 문제가 아니다. 그림이 적은 게임이면 수십 개가 들어간다. 다만 게임마다 남은 수를 확인하는 습관은 필요하다.

5. **이야기 상세 경로에 함정이 여럿 있다 (중요).**
   - **주소에 쓸 id:** 사용자 이야기 id가 `community:<uuid>` 꼴이라 `:` 때문에 기존 상세 셸의 id 검사를 통과하지 못한다. 주소에는 UUID나 정적 slug만 쓰고, 댓글 스레드 키는 지금 그대로 둬야 댓글이 끊기지 않는다.
   - **정적 이야기도 D1을 읽어야 한다:** D1 행이 정적 이야기를 덮어쓸 수 있다(`static_story_id`).
   - **`/#id`를 만드는 곳:**
     - `search-index-data.ts`
     - `comment-threads.ts`
     - `profile-activity.tsx`
     - 패치 댓글 클라이언트
     - 어드민
     - 테스트 두 개
   - **이미 공유된 `/#id`:** 해시는 서버에 오지 않는다. 그래서 홈에 클라이언트 쪽 이동을 계속 둬야 이미 퍼진 링크가 산다.

6. **글자 없는 패널 버튼은 모바일을 해칠 수 있다 (중요).**
   - 지금 모바일에서 백과사전은 한 번 탭이면 열린다. 한 단계가 늘어나는 셈이다.
   - 버튼에 보이는 글자를 붙이고, 패널 첫 칸은 백과사전으로 둔다.
   - 모바일에서는 전체 화면 시트로 연다. Esc, 바깥 탭, 안드로이드 뒤로 가기로 닫히게 한다. 이때 검색 창과 방문 기록 한 칸을 같이 쓴다.
   - 링크 40개 이상은 미리 받기를 꺼서, 패널을 열 때 모바일 데이터를 쓰지 않게 한다.

7. **검색 색인이 조용히 오래될 수 있다 (중요).**
   - `ensure-search-index.mjs`가 감시하지 않는 것: 이야기 JSON, `data/sts1`, 색인이 import하는 `src/lib` 모듈, 앞으로 생길 등록부.
   - STS1을 넣으면 색인이 대략 두 배(gzip 약 314 KB → 600 KB 안팎)로 커질 것으로 보인다. 재 보지는 않았다.

### 서로 부딪히는 요구와 푸는 방법

| 부딪히는 것 | 푸는 방법 | 남는 비용 |
|---|---|---|
| 버튼 하나에 다 숨김 ↔ 찾기 쉬움 | 장난감 상자·백과사전 버튼의 NEW 점을 패널 버튼 하나로 모은다. 접힌 항목도 모두 검색 결과로 나오게 한다. 패널 첫 줄에 최근 방문을 보여 준다. | 점이 하나로 합쳐져 무엇이 새것인지 바로 안 보인다. |
| "항목 하나로 짜퍼 게임 추가" ↔ 정적 빌드의 손으로 쓴 라우트 | JSON 등록부 하나를 Worker 라우트, 복사 스크립트, 패널, 검색이 모두 읽는다. 어긋나면 테스트가 실패한다. | 게임 하나당 정적 파일 28개와 그림은 그대로 든다. 목표 문장은 "등록부 항목 하나 + 게임 페이지"로 쓴다. |
| 정적 빌드 ↔ 동적 이야기 상세 | `history-course/[runId]`처럼 `/stories/__id__` 셸 하나(파일 28개)를 두고, 브라우저가 이야기를 불러온다. 홈에는 `/#id` 이동을 남긴다. | 열 때 요청이 하나 는다. 공유 미리보기를 이야기별로 하려면 `detail-shell-og.ts`를 넓혀야 한다. |
| 이야기 그림 ↔ 사용자 업로드 금지 | 이야기의 `entityType/entityId` → `patchLineId` → 연결된 요소 순으로 기존 그림 주소를 찾는다. 없으면 기본 그림을 쓴다. 홈은 그림 주소를 알아내려고 백과사전 데이터 전체(카드·유물·몬스터 수천 개)를 받으면 무거워진다. 그래서 빌드할 때 이야기가 실제로 참조하는 요소만 골라 `{요소 id: 그림 경로}` 짧은 JSON 하나를 만들고, 홈은 그것만 받는다. | 빌드 스크립트 하나와, 이야기 JSON이 바뀔 때 다시 만드는 조건. 사용자 이야기는 API에서 오므로 표에 없는 요소는 상세에서 따로 찾는다. |
| 더 나은 검색 ↔ 색인 크기·무료 한도 | 점수 단계부터 고친다. 정확히 같은 이름 > 이름의 앞부분 일치 > 이름 중간 일치 > 설명 일치 순으로 점수 칸을 나눈다. 결과는 종류별 고정 순서가 아니라 점수 순으로 보여 준다. 색인에 STS1 요소, 장난감 상자·짜퍼 서비스, 백과사전 인덱스 페이지를 넣는다. 최근에 연 항목은 localStorage에 남겨 같은 칸 안에서 점수를 조금 더한다. 색인이 커지면 이름 파일과 설명 파일로 나눈다. | BM25와 의미 검색은 하지 않는다. 짧은 이름 1,900~4,000개에서는 위 단계만으로 원하는 순서가 나온다. |

### 이미 있는 것으로 할 수 있는 부분

- **패널:** `SiteNavDropdown layout="grid"`(`site-nav-dropdown.tsx`)가 그룹 제목과 하위 항목을 지원한다. 모바일에도 같은 컴포넌트를 쓴다.
- **접기와 하위 묶음:** 장난감 상자 등록부에 `nestedUnder`, `dropdownHidden`이 이미 있다. 그 옆에 `fold` 하나를 더한다.
- **우편함:** 떠 있는 버튼이 이미 있다(`site-navbar.tsx:937-959`). `xl:hidden`을 지우고 데스크톱 링크를 없앤다.
- **죽은 코드:** `encyclopedia-dropdown.tsx`는 아무도 쓰지 않으니 지운다.
- **백과사전 인덱스:** `sts2NavItems`·`sts1NavItems`를 받는 컴포넌트 하나로 `/compendium`과 새 `/compendium/sts1`(28파일)을 그린다. 수는 계산하거나 뺀다. 두 게임을 합친 화면은 패널의 백과사전 칸이 맡는다.
- **새 주소를 추가할 때 고칠 곳:**
  - `static-page-routing.ts`
  - `detail-shell-og.ts`
  - `copy-cf-static-pages.mjs`
  - `workers/path-redaction.ts`
  - `scripts/cloudflare-worker-logs.mjs`

  이 중 `path-redaction.ts`의 목록은 이미 몇 서비스가 빠져 있다.

### 가장 좋은 끝 모습

데이터만 담은 장소 등록부 하나가 기준이다. 빌드할 때 다음이 모두 거기서 나온다.
- 두 상단바와 패널
- 백과사전 인덱스 페이지
- 검색의 서비스·인덱스 항목
- NEW 점

이름이 정확히 일치하면 늘 맨 위에 오고, 첫 글자를 칠 때 받는 데이터는 약 100 KB 아래다. 검색은 서버에 요청을 보내지 않는다. 이야기는 보통 주소라서 뒤로 가기, 공유, 검색이 모두 된다. 짜퍼 게임이나 서비스를 하나 늘릴 때 남는 비용은 라우트당 정적 파일 28개와 그 게임의 그림뿐이다.

## Goals vs. Non-Goals

* **In-Scope Goals:**
  - 상단바: 브랜드, 패치노트, 검색, 프로필, 패널 버튼만 처음부터 보인다. 우편함은 PC·모바일 모두 하단 떠 있는 버튼. 언어는 프로필 안.
  - 패널: 백과사전(STS1·STS2), 장난감 상자(활동 적은 서비스는 더보기 뒤), 짜퍼(하위 게임). 모바일에서는 전체 화면 시트.
  - 패치 Worker의 상단바와 검색도 같은 등록부와 같은 순위 함수를 쓴다.
  - 장소 등록부 하나. 짜퍼 게임 추가는 "등록부 항목 + 게임 페이지"로 끝난다.
  - STS1 백과사전 인덱스 페이지 추가, STS2 인덱스를 패널에서 연결.
  - 검색: 정확 일치 1위, 점수로 정렬, 서비스·백과사전 인덱스·STS1 요소 포함, localStorage 최근 방문 가산.
  - 이야기 상세 경로, 기존 `/#id` 링크 이동, 참조 게임 요소 그림 노출.
* **Out-of-Scope Non-Goals:**
  - 서비스 삭제(접기만 한다).
  - 사용자 이미지 업로드.
  - 옛 주소 `/relics`, `/cards`, `/potions` 처리.
  - 어드민 메뉴 개편.
  - BM25와 의미 검색(semantic search).
  - 메뉴 클릭 기록과 개편 효과 측정. 공급자 주도 개편이다.
  - 언어 선택의 특별 대책. OS·기기 언어로 이미 내려 준다.
  - 홈 방문 감소 원인 분석.

## Alternatives Weighed

- **장난감 상자 저활동 서비스 삭제:** 작성자가 거절. 접어서 남긴다.
- **패널 없이 지금 드롭다운을 줄이기만 하기:** 작성자가 거절. 짜퍼 하위 게임을 늘릴 자리가 바에 없다.
- **BM25:** 넣지 않는다. 짧은 이름 수천 개는 브라우저가 1 ms 안에 다 훑는다. 지금 증상(정확히 같은 이름이 밀림)은 점수 단계와 정렬 두 가지만 고치면(10줄 안팎) 사라진다. BM25는 드문 단어와 짧은 문서를 우대해서, 오히려 패치 요약이 카드 이름보다 위로 올 수 있다.
- **의미 검색:** 넣지 않는다. 항목당 384차원 임베딩이면 약 3.8 MB를 받아야 하고, Workers AI를 쓰면 검색마다 한도가 있는 요청이 하나 는다. 별명이 필요하면 빌드 때 동의어 표로 한다.
- **STS1·STS2를 한 목록에 섞은 통합 백과사전 인덱스 페이지:** 페이지는 게임별 두 개로 두고, 합친 화면은 패널이 맡는다.
- **메뉴 클릭 기록:** 작성자가 거절. 개편 효과를 재는 것보다 짜퍼 게임을 늘리는 것이 목적이다.

## Key Decisions & Staging for Next Steps

이미 정한 것:
- 저활동 서비스는 접는다.
- 짜퍼는 장난감 상자처럼 하위 서비스를 둔다.
- 바에는 검색과 프로필이 남는다.
- 우편함은 PC도 하단 떠 있는 버튼이다.
- 사용자 업로드 그림은 받지 않는다.
- 메뉴 클릭 기록은 넣지 않는다. 공급자 주도 개편이다.
- 언어 선택은 프로필 안으로 옮기기만 한다. OS·기기 언어로 이미 내려 준다.
- 바뀐 배치가 처음에 어색한 건 감수한다.
- 크롤러성 트래픽과 옛 주소는 신경 쓰지 않는다.
- BM25와 의미 검색은 하지 않는다.

제안 순서:

1. **사전 조건:** Supabase 7단계 코드 정리가 `site-navbar.tsx`를 건드리는지 확인한다. 새 라우트마다 `pnpm cf:limits`로 남은 정적 파일 수를 적는다. 2026-11-20 기준 main은 3,036개가 남았고, 알려진 추가분은 STS1 인덱스와 이야기 셸로 약 56개다.
2. **검색 점수 단계를 공유 함수로 고친다.** main과 패치 Worker가 같은 함수를 쓴다. 고정 질의 10개 정도로 테스트한다(조사 붙은 한국어 이름, STS1/STS2 같은 이름 포함). 색인 로드 실패가 지금은 "결과 없음"으로 삼켜지는데, 실패 문구를 따로 보인다.
3. **장소 등록부를 만든다.** 이어서 검색에 STS1·서비스·인덱스를 넣고, STS1 인덱스 페이지와 색인 감시 대상을 추가한다.
4. **이야기 상세 경로를 연다.** `/#id` 이동과 그 링크를 만드는 곳을 모두 바꾼다.
5. **패널, 프로필 안 언어, 떠 있는 우편함을 한 번에 배포한다.** main과 패치 Worker 상단바를 같이 바꾼다.
6. **최근 방문 가산을 넣는다.**
7. **이야기 그림, 그다음 미리보기 릴을 넣는다.** 동작 줄이기(reduced motion) 설정에서는 릴을 끈다.
